# 가입 동의·탈퇴 및 관리자 역할 변경

구현 기준: 2026-09-22. 이 문서는 코드의 동작을 설명하며 법률 검토나 운영 환경 점검을 대체하지 않습니다.

## 가입 동의

- 공개 운영자 `fecu`, 문의 `fecu@kakao.com`: 운영자가 공개를 승인한 값이며 `.env`에서 가져오지 않습니다.
- `/terms`·`/privacy` 및 공용 가입 모달은 같은 본문을 사용합니다.
- 필수 확인란은 이용약관, 개인정보 수집·이용, 만 14세 이상 자기확인으로 구분하며 기본값은 모두 해제입니다. 생년월일·신분증·별도 본인인증은 받지 않습니다.
- 일반 가입 API는 필수 항목과 최신 버전을 검증합니다. 카카오는 가입 모드에서 동의를 받아 15분 HttpOnly 티켓을 발급한 뒤 OAuth로 이동합니다. 동의 없는 신규 콜백은 가입 화면으로 돌아갑니다.
- 로그인 전용 카카오 시도 전과 카카오 콜백 응답 후에 동의 쿠키를 지웁니다. 티켓은 로그인 세션과 서로 다른 salt로 암호화합니다. 만료·변조·이전 문서 버전은 거절합니다.
- 신규 계정 생성과 함께 동의 시각, 문서 버전 2개, 14세 이상 확인을 저장합니다. 기존 회원/관리자 발급 계정의 동의를 소급 작성하지 않습니다. 이번 변경은 자가 가입 경로의 연령 제한이며, 기존/발급 계정에 나이 검증을 도입한 것은 아닙니다.

## 탈퇴 범위와 운영 확인

자기 탈퇴의 `loginIdentifierEncrypted`도 관리자 삭제와 마찬가지로 무작위 삭제용 문자열의
암호문으로 교체합니다. 로그인 조회 키를 무효화하고 비밀번호·프로필을 제거/대체하는 기존 동작은 유지합니다.
앞으로 실행되는 탈퇴에 적용하는 코드 변경이며 이미 탈퇴한 계정이나 백업의 데이터를 소급 삭제하지 않습니다.

게시물·첨부·설문 응답·성적·닉네임 스냅샷 등 학습 기록, 소속 연결, 감사·동의 이력은 이 작업에서
일괄 삭제하지 않습니다. 따라서 처리방침에도 ‘탈퇴 즉시 모든 개인정보 삭제’라고 표시하지 않습니다.
인증 보안 이벤트의 90일 만료 기준 및 후속 인증 요청 시 정리는 기존 코드의 동작입니다.

공개 운영 전에는 운영자가 다음 사항을 실제 운영 환경에 맞게 확인해야 합니다.

- 학습 기록·동의/감사 이력·백업별 보관 필요성과 구체적인 삭제 일정, 삭제 요청 처리 담당자.
- 호스팅·메일·분석 등 코드만으로 확정할 수 없는 위탁, 제3자 제공 및 국외 이전 현황. 해당하면 처리방침에 구체적인 업체·항목·목적·기간 등을 보완해야 합니다.
- 공개 문구는 현재 코드에 맞춘 초안이며 자동으로 법적 적합성을 보장하지 않습니다. 필요 시 전문가 검토를 받습니다.
- 연령 자기확인은 실제 나이 인증이 아니며, 관리자 발급 계정과 기존 이용자에 대한 적법한 처리 근거는 별도로 관리해야 합니다.

## 배포 순서

1. DB 백업과 적용 대상을 확인합니다. `20260922000000_signup_consent`를 앱 교체 전에 `yarn prisma migrate deploy`로 적용합니다.
2. `yarn db:generate` 후 별도 빌드 디렉터리로 빌드·검증합니다. 운영 중인 `.next-prod`에 검증 빌드를 덮어쓰지 않습니다.
3. 승인된 운영 배포 절차로 앱을 교체하고 일반/카카오 신규 가입, 기존 로그인, 동의 기록을 확인합니다.

이 문서는 운영 DB에 마이그레이션이 적용되었다거나 배포되었다는 기록이 아닙니다. 테스트는 가짜 계정과 저장소로 실행합니다.

## 관리자 역할 변경과 검증

학생↔교사 일괄 전환은 학교와 새로운 역할에 맞는 반/부서를 함께 선택해야 합니다. 실패 사유를
사용자별로 표시하고 실패한 선택을 유지합니다. 서버의 권한·소속 검사를 우회하지 않습니다.

```bash
yarn verify:signup-consent
yarn verify:auth-password-ui
yarn verify:admin-bulk
yarn verify:routes
yarn lint
yarn exec tsc --noEmit --incremental false
```

브라우저 테스트에는 Playwright와 Chromium이 필요하며 별도 설치는 `PLAYWRIGHT_MODULE_PATH`로 지정합니다.
새 동의/관리자 테스트는 운영 DB에 쓰지 않습니다. `verify:http` 같은 기존 DB 변경 검증과 혼동하지 마세요.
