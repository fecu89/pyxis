# 보안 유틸 개요

`pii-crypto-core.ts`는 사용자 로그인 식별자(일반 아이디 또는 카카오 이메일)·표시 이름·프로필 이미지 URL을 AES-256-GCM으로 암호화하고, 로그인 식별자·닉네임·인증 제한 키의 목적별 HMAC-SHA-256 인덱스를 생성합니다. `pii-crypto.ts`는 앱에서만 사용하는 `server-only` 경계입니다.

- 모든 암호문은 사용자 ID와 필드명을 AAD로 사용합니다.
- 암호화 키와 검색 키는 서로 분리합니다.
- 키는 서버 환경 변수에서 지연 로딩하며 클라이언트 모듈에서 가져올 수 없습니다.
- 로그나 오류 응답에 암호문, 원문, 키를 포함하지 않습니다.

## 요청 식별과 요청량 제한

`request-identity.ts`는 배포 환경에서 신뢰할 수 있는 프록시 헤더만 골라 요청자를 식별합니다. `proxy.ts`(미들웨어)와 Route Handler가 함께 쓰기 때문에 `server-only`를 붙이지 않으며, 요청 헤더만 읽습니다. `client-ip.ts`는 서버 전용 호출부를 위한 재수출 경계입니다.

- `rateLimitIdentity()`가 제한 키를 정합니다. 로그인 사용자는 계정 단위(`u:{id}`)라 NAT 뒤 공유 IP의 영향을 받지 않고, 비로그인은 **신뢰할 수 있는 IP를 얻을 수 있을 때만** IP 단위(`ip:{...}`)로 셉니다.
- 신뢰할 수 있는 IP가 없는 배포(`TRUST_*` 미설정)에서는 모든 익명 요청이 하나의 버킷으로 묶여 공격자 한 명이 전체 익명 사용자를 함께 막아버리므로, 그 구간은 `null`을 돌려 제한을 건너뜁니다. 해당 구간의 방어는 WAF·프록시 계층 몫입니다.

`rate-limit-core.ts`는 고정 윈도 인메모리 제한기입니다(만료 청소 + 항목 수 상한으로 키 폭증 자체가 메모리 누수가 되지 않게 합니다). `rate-limit.ts`는 서버 전용 경계로 `assertRateLimit()`과 `RateLimitError`를 제공하며, `lib/http.ts`의 `apiError()`가 이를 `Retry-After`가 붙은 429로 변환합니다. 제한기 인스턴스는 `scope`가 아니라 `(windowMs, maxAttempts)` 정책별로 공유하고 최근 사용 32개로 제한합니다. `scope`에는 패드·설문 ID가 들어갈 수 있어 이를 인스턴스 키로 쓰면 새 리소스마다 Map 항목과 sweep interval이 영구히 늘지만, 실제 버킷 키에는 scope가 계속 포함되므로 정책 공유 후에도 리소스별 제한은 분리됩니다. 정책 상한에서 밀려난 제한기는 `dispose()`로 interval과 버킷을 함께 비웁니다.

제한은 두 겹입니다.

1. **전역 백스톱** — `proxy.ts`가 `/api/auth/*`를 제외한 모든 쓰기 메서드에 계정(또는 신뢰 IP)당 분당 200회 상한을 겁니다. 인증 경로는 `lib/auth/security.ts`의 DB 기반 제한이 이미 더 촘촘합니다.
2. **라우트별 좁은 제한** — 비용이 큰 엔드포인트에 별도 상한을 겁니다: 보드 검색(60/분), 보드 활동(120/분), 글·댓글 생성(각 30/분), 첨부 업로드(60/5분), 아바타·배경 이미지(각 20/10분), 링크 미리보기(20/분), 짧은 주소 공개 조회(신뢰 IP별 240/분), 공유 비밀번호 변경(사용자별 10/10분)·원문 조회(5/10분). 공개 보드 비밀번호는 학교 NAT를 고려해 브라우저별 실패 8/10분과 IP 전체 실패 60/10분을 함께 쓰고 성공은 소비하지 않습니다. 로그인 퀴즈 참여는 인증 뒤 사용자 ID로 세므로 학교 NAT 학생끼리 충돌하지 않습니다.

비싼 scrypt는 이벤트 루프를 막지 않는 비동기 API와 동시 4개·대기 32개 작업 큐를 사용합니다. `/go` DB 조회도 동시 24개·대기 96개로 제한하고 동일 slug의 진행 요청을 합칩니다. 이 상한은 단일 프로세스 보호이며, 분산 공격은 Cloudflare WAF의 `/go/*`·공개 비밀번호 확인 경로 제한을 함께 적용해야 합니다.

인메모리라 다중 인스턴스에서는 인스턴스별로 따로 셉니다. 인증 경로처럼 DB 기반으로 옮기거나 공유 저장소가 필요합니다(structure.md §8).
