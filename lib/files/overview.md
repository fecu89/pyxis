# 파일 처리 개요

pyxis는 현재 오브젝트 스토리지 없이 `UPLOAD_DIR` 아래의 로컬 영구 디스크에 첨부파일을 저장합니다.

- multipart 본문은 `request.formData()`로 메모리에 올리지 않고 Busboy로 임시 파일에 스트리밍합니다. Busboy의 `parts` 한도는 `fields` 한도와 달리 배타적입니다 — `fields`는 한도 값까지 통과시키지만 `parts`는 한도 값에서 바로 걸립니다(실측 확인). `streamMultipartFile`(`multipart.ts`)이 파일 1개 + 허용 필드 전부를 받고도 통과하도록 `parts` 한도에 `+2`를 둔 이유입니다. 허용 필드가 1~2개뿐인 라우트(프로필 사진 등)는 한도에 여유가 있어 이 경계에 걸리지 않았고, 필드 3개(`prefix`·`mode`·`reason`)를 모두 쓰는 학생 명단 발급 라우트에서만 실제로 걸렸습니다.
- `proxy.ts`가 업로드 API도 통과시키므로 Next의 요청 본문 복제 상한은 Admin에서 입력 가능한 최대 업로드값보다 5MB 크게 둡니다. 실제 파일 상한은 이 인프라 상한이 아니라 매 요청마다 읽는 현재 Admin 정책이며, multipart 경계·파트 헤더가 파일 밖에 붙는 점을 고려해 전체 전송 본문에만 5MB 여유를 둡니다. 예를 들어 Admin 값이 30MB이면 파일은 30MB까지, multipart 본문은 35MB까지 허용됩니다.
- 확장자만 믿지 않고 파일 시그니처를 검사합니다.
- 이미지(JPEG, PNG, WebP, GIF)는 방향을 보정한 뒤 최대 2560×2560, 품질 82의 WebP로 변환합니다. 업로드한 원본 이미지는 남기지 않습니다.
- 카드용 썸네일은 최대 960×960, 품질 76의 WebP로 별도 생성합니다.
- Sharp 변환은 전역 동시 실행 제한을 사용해 여러 사용자가 동시에 업로드해도 CPU와 메모리가 급격히 치솟지 않게 합니다.
- 문서 파일은 스트리밍된 임시 파일을 원자적으로 이동하며, 다운로드도 Node 스트림과 Range 요청을 사용합니다.
- Office 문서 PDF 변환은 같은 파일의 동시 작업을 `inFlight` 한 건으로 합치고, 파일 검사 단계 전부터 활성+대기 상한을 적용해 폭주 요청의 Promise가 큐 앞에 무한히 쌓이지 않게 합니다. 실패는 15분 동안 기억하되 서로 다른 잘못된 경로가 계속 들어와도 최대 512개이며, 새 실패를 넣기 전에 만료 항목과 가장 오래된 항목을 지웁니다.
- 영상은 MP4·WebM·MOV, 음성은 MP3·M4A·WAV·OGG·WebM만 허용합니다. 미디어는 원본을 트랜스코딩하지 않고 저장하되 확장자와 컨테이너 시그니처가 일치해야 하며, 재생은 Range 요청을 사용합니다.
- WebM은 음성·영상이 같은 컨테이너 시그니처를 사용하므로 시그니처를 먼저 검증한 뒤 브라우저가 보낸 MIME을 표시 유형 구분에만 제한적으로 사용합니다. **주의**: 브라우저가 보낸 MIME은 `MediaRecorder.mimeType`을 그대로 반영하므로 `audio/webm;codecs=opus`처럼 코덱 파라미터가 붙는 경우가 흔합니다 — `validateUploadedFile`(`validation.ts`)의 판별 조건은 이 파라미터가 붙은 문자열도 인식해야 하며, 정확히 `"audio/webm"`과만 비교하면 실제 녹음 파일이 전부 VIDEO로 잘못 분류됩니다(과거 버그, 수정됨 — `components/pad/attachments/overview.md` 참고).
- 디스크 저장명은 충돌과 경로 조작을 막기 위해 `UUID + 검증된 확장자`를 사용합니다.
- multipart 파일명은 UTF-8로 해석합니다. 사용자에게 보이는 파일명은 Unicode NFKC로 정규화하고, 경로·제어·예약 문자를 제거하며, 공백은 `_`로 치환합니다. 변환된 이미지는 실제 형식에 맞게 `.webp` 확장자로 표시합니다.
- 첨부 하나 또는 첨부가 든 게시글·댓글·섹션을 삭제하면 원본·썸네일·문서 미리보기와 Attachment 행을 즉시 영구 정리합니다. 파일 시스템 오류가 나면 숨김 행을 재시도 표식으로 남기며, 서버 시작 1분 뒤와 이후 7일마다 실행되는 `pad-trash-sweep`가 다시 정리합니다. 글·댓글·섹션·패드의 DB 내용은 7일 동안 복구할 수 있지만 첨부파일은 복구하지 않습니다.
- 패드 배경은 `UPLOAD_DIR/boards/{boardId}/background.webp` 한 장만 유지합니다. JPG·PNG·WebP 입력을 최대 10MB로 스트리밍하고 시그니처 검사·40MP 입력 픽셀 제한·Sharp 동시 처리 제한을 거쳐 최대 1920×1200, 품질 82 WebP로 다시 인코딩하므로 원본 메타데이터나 이미지에 위장한 HTML/스크립트는 서비스되지 않습니다. 교체는 임시 파일을 원자적으로 이동하고, 패드 영구 삭제는 해당 보드 업로드 디렉터리 전체를 정리합니다.
- `store-upload.ts`는 게시물과 댓글 첨부가 같은 Busboy 스트리밍, 파일 시그니처 검사, WebP 변환, 처리 동시 실행 제한과 안전한 저장명 생성을 공유하게 합니다. 라우트는 저장 결과를 받은 뒤에만 소유 대상과 연결된 Attachment 행을 만듭니다.
- 링크 첨부는 로컬 파일이 없으므로 `storedName`·`storagePath`가 null이고 `externalUrl`을 사용합니다.
  미리보기에서 검증된 일반 웹 대표 이미지는 nullable `previewImageUrl`에 함께 저장해 카드 렌더링 때
  외부 HTML을 다시 가져오지 않습니다. 파일 서빙과 영구 정리는 null 경로를 건너뛰며, 링크나 대표
  이미지를 내부 파일처럼 프록시하지 않습니다.
- 댓글 첨부는 원본 게시물 ID와 댓글 ID를 함께 저장합니다. 이미지·음성만 허용하고 댓글당 최대 4개를 행 잠금 트랜잭션으로 강제합니다. 댓글 삭제 시 연결 첨부는 즉시 영구 삭제하며 댓글 본문만 7일 동안 복구할 수 있습니다.
- `altText`와 `caption`은 파일 자체와 분리된 메타데이터로 편집합니다. `sortOrder` 변경은 게시물의 삭제되지 않은 첨부 ID 전체가 정확히 일치할 때만 트랜잭션으로 적용합니다.
- 게시물 파일과 링크는 같은 게시물 행을 잠근 트랜잭션에서 합계 20개 제한과 다음 `sortOrder`를 계산합니다. 댓글 첨부도 댓글 행 잠금으로 4개 제한을 강제하므로 2~3개의 병렬 업로드가 제한을 우회하지 못하며, 제한 초과는 사용자 입력 오류 400으로 반환합니다.

운영 조정 환경 변수는 `UPLOAD_DIR`, `MAX_UPLOAD_SIZE_MB`(기본 30), `IMAGE_PROCESSING_CONCURRENCY`(기본 2, 최대 4)입니다. 로컬 디스크를 사용하므로 단일 앱 인스턴스와 영구 볼륨, 정기 백업이 전제입니다.

퀴즈 이미지(문항 이미지·퀴즈 썸네일)도 여기 규칙을 따릅니다. 예전에는 브라우저 canvas로 줄인 base64 data URL을 DB 컬럼(`Question.imageUrl`, `Quiz.thumbnailUrl`)에 통째로 담았지만, 지금은 `UPLOAD_DIR/quiz/{quizId}/{uuid}.webp`에 파일로 두고 컬럼에는 주소만 남습니다. 저장·정리 헬퍼는 `lib/quiz/image-store.ts`, 접근 판정은 `lib/quiz/image-access.ts`입니다.

- 서버 sharp가 시그니처 검사 뒤 다시 인코딩합니다(문항 이미지는 긴 변 1600 WebP, 썸네일은 긴 변 800 JPEG). **썸네일만 JPEG인 이유**: og:image로도 나가는데 카카오톡 등 일부 링크 미리보기가 WebP를 렌더하지 못합니다. 투명 배경은 흰색으로 합성합니다.
- 문항별이 아니라 퀴즈별 디렉터리인 이유: 편집기는 아직 저장되지 않은 문항(clientId만 있는 상태)에도 사진을 올릴 수 있어, 업로드 시점에 확정된 ID가 `quizId`뿐입니다. 참조되지 않은 파일은 동시 편집을 위해 24시간 보존한 뒤 퀴즈 저장 시와 서버의 기본 6시간 주기 sweep에서 정리합니다(`.uploading` 임시 파일은 건드리지 않습니다). 파일·퀴즈별 총량은 관리 페이지의 업로드 정책에서 조정합니다. 기본 90일이 지난 삭제 퀴즈는 응시 세션이 없을 때만 DB와 파일을 함께 정리하며 `QUIZ_DELETED_PURGE_DAYS=0`으로 끌 수 있습니다.
- 퀴즈 복제는 주소만 베끼지 않고 **파일을 복사**합니다. 주소를 공유하면 원본 퀴즈를 지울 때 사본의 사진까지 사라집니다.
- DB에 저장하는 내부 주소는 현재 퀴즈 ID와 파일 종류(썸네일 JPEG, 문항 WebP)가 일치하고 파일이 실제로 있어야 합니다. 다른 퀴즈의 주소를 넣어 공개/복제 권한을 우회할 수 없습니다.
- 퀴즈 삭제는 먼저 소프트 삭제합니다. 지난 세션 리포트·참여 이력이 있으면 이미지와 문항을 계속 보존하고, 응시 세션이 전혀 없는 삭제 퀴즈만 보존 기간 뒤 sweep가 영구 정리합니다.
- 서빙은 로그인 사용자의 퀴즈 접근 권한만 보지 않습니다. 이 퀴즈 세션에 참여 등록된 학생과, 공개 세션에 닉네임으로 들어온 손님(세션별 HttpOnly 쿠키)도 통과해야 수업 중 학생 화면에서 문항 이미지가 뜹니다. 권한 없음과 없는 파일은 똑같이 404로 돌려줘, 주소만으로 남의 퀴즈에 어떤 사진이 있는지 떠볼 수 없게 합니다.
- 화면은 전부 `next/image`의 `unoptimized`로 그립니다. 최적화 경로(`/_next/image`)는 쿠키 없이 원본을 가져오므로 인증이 걸린 이 라우트에서는 404가 됩니다.
- 옮기기 전에 쌓인 data URL은 `yarn db:backfill-quiz-images`(`--dry-run` 지원)가 50건씩 파일로 내립니다. DB 원본이 그대로일 때만 조건부 갱신하므로 실행 중 편집을 덮어쓰지 않으며, 신규 저장에서는 `data:`를 받지 않습니다.

프로필 사진은 게시물 첨부와 별도 경로(`UPLOAD_DIR/avatars/{userId}/avatar.webp`)에 저장합니다. Attachment 테이블에 연결되지 않는 단일 파일이라 30일 복구 이력을 두지 않고 새로 올리면 덮어쓰며, 512×512 WebP로만 변환합니다. 경로 헬퍼는 `paths.ts`의 `getAvatarDirectory`/`getAvatarPath`이며 사용자 ID 형식을 검증해 경로 조작을 막습니다.
## Pad 게시물 비동기 이미지 처리

`image-intake.ts`/`image-metadata.ts`는 안전한 초기 이미지를 준비합니다.
`image-job-store.ts`, `image-worker.ts`, `image-job-cleanup.ts`는 DB 기반 임대·변환·파일 정리를
담당하며 `server.ts`에서 시작됩니다. `attachment-url.ts`는 revision 기반 표시와 병합,
`attachment-read.ts`는 파일 교체와 복사/내보내기의 경합을 처리합니다.
설정과 롤백은 `docs/pad-background-images.md`를 참고하세요.
