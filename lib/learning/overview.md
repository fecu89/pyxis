# 학생 학습 진입

- 대시보드, 교과목 바로가기, 학생 퀴즈·설문 목록에서 사용하는 최소 읽기 모델입니다.
- 교과목 상세는 `getCourseAccess`로 관리 권한/수강 권한을 먼저 구분합니다. 학생 배정 권한이
  있는 소유자만 관리 컴포넌트와 학생 명단을 읽습니다. 학생 소유 교과목도 관리 권한을 주지
  않으며, 명단·후보·구성 변경 API에 동일한 경계를 적용합니다. 관리 UI는 client lazy 경계로
  분리합니다. 개별 배정과 연결 학급의 활성 학생은 학생용 활동 모달을 받습니다.
- 학생 개인 교과목 분류는 유지하되, 패드 생성·교과목 연결 시 명단 자동 초대는 공통 초대 함수에서
  관리 역할을 확인한 뒤에만 실행합니다. 역할 하향 후 남아 있는 명단도 학생에게 노출하지 않습니다.
- 모달은 공용 `Modal`을 사용하며 종류를 선택할 때 `/api/me/learning`에서 최대 24개씩 읽습니다.
  교과목 ID를 직접 바꿔 보내도 같은 권한 검사를 적용합니다. 응답은 `private, no-store`입니다.
- 학생 전체현황·교과목 모달·학습 목록은 퀴즈/패드의 `ContentCard`·`ContentCardGrid`·
  `ContentCardBadge`와 공용 `EmptyState`를 그대로 사용합니다. 관리 메뉴는 전달하지 않고,
  실행할 수 없는 과제는 링크 없는 카드로 표시합니다. 모달의 카드 열 수는 화면 전체가 아닌
  실제 영역 폭을 따르며, 전체현황 요약은 공용 `StatCard`를 사용합니다.
- 퀴즈는 `quiz-queries.ts`가 열린 교과목 라이브 → 미완료 자율 과제 → 수업 대기 → 지난 결과
  순서로 조회합니다. 묶음별 count/skip/take로 합성 페이지를 만들며 전체 이력을 읽지 않습니다.
  교과목의 발행 퀴즈는 개별 할당 없이도 대기/라이브 카드가 나타나지만 방은 교사가 직접 엽니다.
  다른 공유 교사가 연 방은 노출하지 않고 과목 소유자가 연 방만 연결합니다. 개인 과제는 기존
  `QuizAssignment`의 ASYNC 세션을 그대로 사용하며, 같은 퀴즈의 라이브와 과제 기록은 별개입니다.
  대기 카드는 링크가 없고, 초안·삭제 퀴즈·강퇴된 라이브는 제외합니다. 원본 편집 권한은 주지 않습니다.
- 라이브 참여는 기존 `/j/:pin?subjectId=...`로 연결합니다. `assertCourseLiveAccess`가 GET과
  로그인/공개 참여 POST에서 현재 수강 여부·과목/호스트·발행 상태·열린 LIVE를 다시 확인합니다.
  subjectId 없는 기존 PIN/QR 공유 참여는 유지합니다. 공개 라이브는 기존 닉네임·게스트 쿠키 방식이며
  계정 기반 지난 결과는 로그인 라이브만 표시합니다. 과제와 종료한 로그인 라이브는 본인 결과로 연결합니다.
- 학생 대시보드/퀴즈 페이지와 모달 퀴즈 탭은 보이는 동안 15초마다 갱신하고 창 복귀 시 갱신합니다.
  모달은 진행 중인 요청을 중복하지 않으며 탭 변경/닫기에서 요청·타이머를 정리합니다.
- 교사 퀴즈 목록의 세션 모달에서 기존 학생 선택/할당 모달로 바로 이동할 수 있습니다.
  `자율 풀이 과제 할당`과 기존 `자율 풀이 링크`를 구별해 링크 생성만으로 할당됐다고 오해하지 않게 합니다.
- 패드는 소유/멤버십 범위입니다. 수강 교과목 안에서는 원래 읽을 수 있는 LINK/PUBLIC도 표시하지만
  PRIVATE 멤버십이나 보드 비밀번호 검사를 우회하지 않습니다.
- 설문은 수강 교과목 또는 본인 응답 이력이 있는 OPEN/CLOSED만 표시하고 `/s/:slug`로 연결합니다.
  초안·문항 정의·다른 사람의 응답·응답 관리 링크를 보내지 않습니다. 응답 가능 여부는 기존 응답
  화면/API가 다시 판단합니다. 설문 교과목 연결은 기존 `Form.subjectId`와 소유권 검사를 재사용합니다.
- 교사에서 학생으로 역할이 바뀌어 소유/공유 기록이 남아도 설문 관리 데이터는 읽지 않습니다.
  이는 관리 경계이며 공개 응답 경로에는 적용하지 않습니다.
- `yarn verify:learning`: 실제 서버 조회/페이지/API를 인증·DB fixture로 검사하고 실제 학생 모달을
  Chromium에서 검사합니다. 운영 DB를 사용하지 않습니다. 외부 Playwright 설치는
  `PLAYWRIGHT_MODULE_PATH`로 지정합니다.
