# Overview

사용자 선택 후 일괄 역할 변경에서 학생/교사를 고르면 학교와 해당 역할에 맞는 반/부서를 함께
선택·저장합니다. 기존 반을 남긴 채 교사 역할만 보내던 실패를 방지하며, 서버 권한 검사는
유지합니다. `skipped` 사유는 사용자별로 표시하고 실패한 대상은 목록 갱신 후에도 선택을 유지해
재시도할 수 있습니다. 운영 DB 없는 Chromium 회귀 검증: `yarn verify:admin-bulk`.

`/admin/*` 사용자·권한 관리 화면의 Client Component 모음입니다. 사용자 권한 관리 목록은 이름과 전체 로그인 식별자를 표시하고, 프로필 URL 같은 나머지 원문 개인정보는 명시적인 조회 작업에서만 일시 응답으로 표시하며 조회 기록을 감사 로그에 남깁니다.

`types.ts`의 `UserRole`·`UserStatus`·`SystemPermission`은 손으로 적지 않고 `generated/prisma/enums`에서 가져옵니다. quiz 병합으로 `SystemPermission`이 12개에서 16개로 늘었을 때 손으로 적은 유니온은 조용히 뒤처져 서버가 내려준 값을 타입이 거부하는 상태가 됩니다. 생성 타입을 쓰면 `Record<SystemPermission, string>`인 권한 라벨 맵이 컴파일 단계에서 누락을 잡아줍니다.

- 사용자 목록은 이름·닉네임·일반 아이디·카카오 이메일 부분 검색과 10·50·100명 페이지네이션을 제공합니다. 검색 버튼 없이 2자 이상 입력하고 350ms 멈추면 자동으로 조회하며, 입력을 지우거나 1자로 줄이면 전체 목록으로 돌아갑니다. 정확한 이름·아이디는 HMAC 조회로 놓치지 않고, 넓은 부분 검색이 1,000명 복호화 범위를 넘으면 필터를 더 좁히도록 안내합니다. 목록 카드에는 일반 로그인 아이디를 전부 표시하고 긴 카카오 이메일은 축약하며, 상세 작업 모달에서는 전체 식별자를 확인할 수 있습니다. 역할·상태·학교·반/부서 필터는 선택 즉시 적용되며, 소속 선택지는 학생 반과 교사 부서로 나뉩니다. 일반 교사는 자기 학교 학생 번호만 수정하며 일괄 선택과 다른 행 작업은 비활성화됩니다.
- `정책` 탭은 학생·교사가 소유할 수 있는 최대 **패드·퀴즈** 개수와 보안 상한을 정합니다. 퀴즈 한도는 비워 두면 무제한이라(교사 기본값) 빈 문자열을 `null`로 다루고, 패드 한도에는 그런 개념이 없어 항상 숫자입니다. 학교 NAT의 100명 수업을 막지 않도록 IP별 공개 퀴즈 소켓 기본값은 200이며, 참가자별 탭 상한과 프로세스 전체 상한은 별도로 유지합니다.
- `퀴즈 사운드` 탭의 `quiz-live-audio-settings.tsx`에서는 전체관리자가 대기실/진행 BGM과 시작·카운트다운·점수·종료·TOP 3 효과음을 업로드·미리듣기·삭제하고 BGM/효과음 볼륨을 따로 저장합니다. 오디오는 MP3·M4A·WAV, 슬롯당 12MB 이하이며 설정하지 않은 슬롯은 재생하지 않습니다. 정책 조회와 분리되어 한쪽 설정의 스키마 문제가 다른 화면까지 막지 않으며, 오디오 메타데이터는 서버 페이지가 초기 prop으로 주므로 패널 마운트 뒤 중복 GET이나 로딩 깜박임이 없습니다. 7개 미리듣기도 `preload="none"`이라 사용자가 재생한 파일만 요청합니다. 정책과 오디오 변경은 모두 감사 로그에 남습니다.
- `테마` 탭(`theme-panel.tsx`)은 사이트 전체 브랜드 색을 정합니다. 저장되는 값은 색상각과 채도 배율 두 숫자뿐이고(`SystemSetting.brandHue`/`brandChroma`), 나머지 색은 CSS가 파생시킵니다. 미리보기와 프리셋 버튼은 색을 따로 계산하지 않고 `.theme-scope`를 얹어 **실제 토큰을 그대로** 그리므로 여기 보이는 색이 곧 저장 후 화면 색입니다. 편집 중에는 `<html>`에도 값을 얹어 사이드바·표처럼 미리보기 상자에 넣기 어려운 실제 화면으로 확인할 수 있고, 저장하지 않고 떠나면 다음 요청에서 서버 값으로 돌아옵니다. 변경은 감사 로그에 전후 값이 남습니다.
- `학교 대시보드`는 학생·교사·학급 수와 번호/학급 미지정 학생만 보여주고 사용자 명부·소속 관리·학생 계정 발급으로 바로 연결합니다. 학교 하나를 고르면 코드·급별·지역·운영 상태를 같은 화면에서 관리합니다.
- 별도 학급·담임 메뉴는 두지 않습니다. 학급과 부서는 `소속 관리`에서 편집하고, 학생만 일괄 선택한 사용자 작업 막대에서는 다른 수정과 상호 배타적인 `반 이동`을 열어 도착 반의 빈 번호를 자동 배정합니다.
- 시스템 권한·학교 대표교사·개인정보 조회·세션 해제·비밀번호 초기화·회원 삭제처럼 드물거나 민감한 작업은 행마다 렌더링하지 않고 `⋯` 버튼을 누른 사용자 한 명의 모달에서만 처리합니다. Credentials 계정은 무작위 임시 비밀번호 초기화 또는 관리자가 직접 입력한 비밀번호 지정 중 고를 수 있고, 어느 쪽이든 세션을 모두 해제하고 다음 로그인에 다시 바꾸게 강제합니다(무작위일 때만 응답에서 평문을 한 번 표시). 학생 대상은 전체관리자·학생 계정 발급 권한 보조관리자뿐 아니라 같은 학교 대표교사도 할 수 있습니다 — 관리자급(교사·보조관리자·전체관리자) 대상은 대표교사를 제외하고 기존 세션 해제 권한 기준(전체관리자, 또는 `REVOKE_USER_SESSIONS` 권한이 있는 보조관리자가 교사 대상)을 그대로 씁니다.
- 현재 페이지에서 여러 회원을 골라 역할·상태·소속을 일괄 변경하거나, 전체관리자는 선택 회원을 일괄 삭제할 수 있습니다. 선택 작업은 목록을 아래로 밀어내는 인라인 폼이 아니라 화면 오른쪽 아래의 소형 플로팅 창에서 수행하고, 역할·상태·소속·반 이동 중 현재 고른 작업의 입력만 표시합니다. 마지막 행도 창 위로 스크롤할 수 있도록 목록 끝에는 선택 중에만 여백을 둡니다. 현재 로그인한 관리자와 권한 밖 대상은 서버가 제외하고 결과를 구분해 반환합니다.
- 사용자 목록 위의 "N명 선택됨 / 전체선택 / 전체 해제" 툴바는 admin 전용 클래스(`admin-table-toolbar*`)가 아니라 `components/ui/selectable-list.tsx`가 정의한 공용 `.select-toolbar`/`.select-toolbar-actions`/`.select-toolbar-button`을 씁니다 — 문구·`selectAllUsers`/`deselectAllUsers` 로직·shift 범위 선택 앵커는 이 파일이 그대로 들고 있고 클래스만 이관했습니다. `UserCard`의 행 선택 시각 효과(hover 배경·선택 시 좌측 강조선·선택된 아바타)도 `app/globals.css`에서 `.select-row`/`.select-row-avatar`와 셀렉터를 그룹화해 같은 선언을 공유하므로, 색 토큰을 한 곳만 고치면 admin 사용자 목록과 다른 `SelectableList` 화면(교과목 명단, 퀴즈 공유·할당)이 함께 바뀝니다.
- 전체관리자는 학교, 전체관리자·학교 대표교사는 반·부서를 관리합니다. 학교를 펼치면 학교 대표교사 영역과 `학생 학급(CLASS)`·`교사 부서(DEPARTMENT)` 영역으로 나뉩니다. 전체관리자는 활성 교사를 대표로 지정·해제하고, 학생 쪽은 연결선과 들여쓰기로 학교 → 학년 → 반 → 학생 위계를 보여줍니다. 인원 버튼은 전체 로그인 식별자를 포함한 구성원을 20명씩 지연 조회하고 학급 학생마다 번호 입력을 제공합니다. 일반 교사도 자기 학교 구조와 구성원을 읽고 번호를 수정할 수 있지만 구조 편집 폼은 보이지 않습니다.
- `학생 계정 발급`은 소속 관리 아래의 독립 사이드바 메뉴입니다. `.xlsx` 양식 다운로드 → 3MB·최대 500명 명단 미리보기 → 충돌 확인 → 계정 발급 순서이며, 학교·학년·반과 사용자를 함께 생성합니다. 결과의 아이디·초기 비밀번호는 한 번 표시하고 UTF-8 CSV로 내려받을 수 있습니다.
- `가입 승인`과 `교사 가입 요청` 메뉴는 체크박스를 노출하지 않는 공용 `SelectableList`를 사용합니다. 행 클릭·Shift 범위 선택·현재 화면 전체선택으로 여러 요청을 고른 뒤 `선택 승인`으로 한꺼번에 처리할 수 있고, 개별 승인·반려 버튼도 그대로 제공합니다. 교사 요청은 전체관리자에게 모든 학교, 학교 대표교사에게 자기 학교 신청만 보여줍니다.
- 관리자 작업은 사유 입력칸 없이 실행하며 작업 종류와 대상에서 감사 설명을 자동 생성합니다. 회원 삭제처럼 되돌릴 수 없는 작업은 확인 모달을 거치고, `DELETED` 상태·세션 버전 증가·개인정보 제거와 감사 로그 기록은 그대로 유지합니다.

## 디자인 정합 (`adminExp` 검토 결과 반영)

`adminExp` 시안에서는 학교 지표·점검 목록·반 이동·학교 정보의 기능 구조만 가져왔습니다. 프로젝트에 필요하지 않은 전출·재적 상태·담임·정원·진급은 UI·API·DB에서 제거했습니다. 시안의 serif/newsprint 외형과 별도 탭 내비게이션은 복제하지 않고, `app/globals.css`의 공용 의미 토큰과 Pretendard를 사용합니다. 관리자 셸은 `학교 운영`·`콘텐츠`·`시스템`으로 그룹화한 고정 탐색 열과 넓은 단일 작업 면으로 구성하고, 모바일 상단에는 현재 메뉴명을 표시합니다. 정책은 세 설정 구역과 sticky 저장 바로 나뉩니다. 전체 패드·퀴즈·설문은 데스크톱에서 표를 유지하되 640px 이하에서는 가로 스크롤 대신 핵심 필드를 가진 카드형 행과 접을 수 있는 상세 필터를 사용합니다. 다크 모드도 같은 의미 토큰을 공유합니다.

보호자 연락처는 수집 목적·열람 범위·보존 정책이 현재 프로젝트에 없으므로 추가하지 않았고, 메일 제공자가 없는 상태에서 동작하지 않는 교직원 초대 UI도 만들지 않았습니다. 기존 교사 가입 승인과 학생 XLSX 계정 발급 흐름을 재사용합니다.

`resources/`에는 `전체 패드`(`board-manager.tsx`, `VIEW_ALL_BOARDS`)와 같은 모양의 `전체 퀴즈`(`quiz-manager.tsx`)·
`전체 설문`(`form-manager.tsx`) 탭을 모았습니다. 셋 다 검색·소유자 정확 검색·수정일 범위·보관 토글·
정렬 가능한 7열 테이블·offset 페이지네이션이 동일한 구조이고, `.admin-manager-badge`(잠김/템플릿
같은 작은 배지)와 테이블 열 너비 CSS 규칙을 공유합니다. 퀴즈·설문에는 `/report`가 다루지 않는
발행 상태·로그인 필요 여부·잠김 상태(소유자 계정 삭제 후 승계자 없음) 같은 구조 데이터가 있어
따로 둡니다. 설문에는 별도의 조회 권한이 없어(`lib/forms/list.ts`도 같은 권한으로 판정) 퀴즈와
같은 `VIEW_ALL_QUIZZES`(또는 `EDIT_ANY_QUIZ`) 권한을 재사용합니다 — `VIEW_ALL_FORMS` 권한은
따로 없습니다.

세 관리기가 복제하던 검색·날짜·보관 필터와 정렬 헤더는 `resources/resource-manager-ui.tsx`, 쿼리 직렬화는 `resources/resource-manager-query.ts`가 담당합니다. 사용자·학교·리소스·교사 승인 목록이 각각 복제하던 페이지 번호 창과 이전/다음 버튼은 `shared/admin-pagination.tsx` 하나로 합쳤고, 역할 라벨도 `shared/labels.ts`를 정본으로 사용합니다. `shared/`는 admin 안에서만 공용인 요소이고, 제품 전체에서 쓰는 요소는 `components/ui`로 올리는 것이 폴더 경계입니다.

## 성능 경계

`app/admin/layout.tsx`는 인증·권한·사이드바만 렌더링합니다. 사용자·감사·학교 관리·승인·정책·사운드·패드·퀴즈·설문은 각각 `app/admin/<section>/page.tsx`에서 필요한 조회만 실행합니다. 공통 셸은 목록 count도 조회하지 않으며, 사이드바 링크는 `prefetch={false}`라 첫 진입 때 다른 관리자 페이지 RSC를 미리 요청하지 않습니다. 사용자 목록 상태는 `admin-users-panel.tsx`, 감사 로그 상태는 `admin-audit-panel.tsx`에만 들어가 다른 관리자 페이지의 클라이언트 청크에 섞이지 않습니다.

사이드바 이동은 `/admin/users`처럼 정식 URL을 바꿔 해당 Server Component만 받습니다. 사용자·감사 및 전체 패드·퀴즈·설문 필터 요청은 새 요청 전에 이전 `fetch`를 abort하고, 언마운트 때도 취소합니다. 빠르게 필터를 바꿨을 때 오래된 응답이 최신 화면을 덮거나 대용량 응답이 닫힌 페이지 상태를 붙잡지 않습니다.

전체 콘텐츠 표의 반복 외부 열기 링크도 자동 prefetch를 끕니다. 표에 보이는 25개 패드·퀴즈·설문의 상세 RSC를 관리자 목록 진입과 동시에 요청하지 않습니다.
