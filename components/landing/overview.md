# 공개 랜딩 UI

`app/(marketing)/page.tsx`의 로그인 없는 공개 홈페이지를 담당합니다. 작업공간 데이터와 세션을 조회하지 않고, 검색 파라미터의 인증 오류·로그인 요청·안전한 내부 콜백 경로만 받아 `LandingPage`에 전달합니다.

- `landing-page.tsx`: Server Component로 브랜드 헤더, 소개, CSS 기반 패드 화면 예시, 기능·학생/교사 가입 흐름, 대시보드 CTA를 렌더링합니다. 비트맵 목업을 내려받지 않고 로그인·테마 버튼만 작은 Client Component로 두어 첫 화면 이미지와 JS 요청을 늘리지 않습니다.
- `landing.module.css`: 공개 화면 전용 반응형 스타일입니다. 앱의 역할 기반 색상 토큰만 사용하므로 전역 라이트·다크 테마를 그대로 따르고, 980px과 720px에서 각각 태블릿·모바일 구조로 재배치합니다.
- 로그인 버튼은 `HomeAuthActionsProvider`의 일반 로그인·회원가입·카카오 흐름을 재사용하고 성공 후 기본 목적지는 `/dashboard`입니다. `/b/...` 같은 보호 경로에서 `/?login=1&callbackUrl=...`로 온 경우 검증된 내부 경로를 유지합니다.

`/`는 브랜드와 서비스 설명을 위한 공개 경로이고, 로그인 후의 진입점은 `app/(workspace)/dashboard/page.tsx`의 `/dashboard`입니다. 공개 랜딩에는 사용자별 정보나 공개 패드 목록을 서버에서 조회하지 않습니다.

## 카피의 초점: 패드 하나가 아니라 패드·퀴즈·설문 → AI 생기부

이 페이지는 원래 pad 단일 프로젝트 시절 카피 그대로 "협업 패드"만 설명했습니다. quiz·forms를 병합하고
AI 생기부 문안 초안(`app/(workspace)/report/writeup/page.tsx`)이라는 방향이 잡힌 뒤에도 홈 화면 카피는
갱신되지 않아, 실제로는 세 활동을 모아 생기부까지 잇는 플랫폼인데 첫 화면만 "패드 서비스"로 보였습니다.

지금 `featureItems`는 패드 → 퀴즈 → 설문 → AI 생기부 순서로 4장을 둡니다. 마지막 "AI가 생기부 초안까지"
카드는 아직 구현 전인 기능을 가리키므로, 문구는 "완성해 드립니다"가 아니라 "초안을 정리해요"처럼 결과물의
성격(초안)을 벗어나지 않게 씁니다 — 실제로 눌러 보면 `/report/writeup`은 아직 준비 중 화면인데, 카피가
이미 완성된 기능처럼 말하면 안 되기 때문입니다.
