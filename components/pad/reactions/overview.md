# 게시물 반응 컴포넌트 개요

이 폴더는 좋아요·하트·축하·웃음·놀람과 보드에서 허용한 사용자 정의 이모지 반응을 표시합니다.

- 반응 UI는 현재 집계와 사용자의 반응 목록을 props로 받고, 변경은 `onToggle` 콜백으로 위임합니다.
- (사용자 UX 피드백 반영) 기본 반응 5종을 예전에는 항상 인라인으로 다 띄웠는데("왜 쓸데없이 이렇게 많냐"), 이제는 실제로 개수가 있거나 내가 누른 반응만 인라인 pill로 보여줍니다. 새 반응은 `SmilePlus` 아이콘 트리거를 눌러야 열리는 팝오버(기본 5종 + 커스텀 이모지 그리드)에서 고릅니다 — 팝오버 안 기본 반응 버튼도 현재 내가 누른 상태를 `data-selected`로 표시합니다.
- 팝오버는 `position: fixed` + `createPortal(..., document.body)`로 띄웁니다. 처음엔 `.picker`(트리거를 감싸는 span) 기준 `position: absolute`였는데, 게시물 카드 목록(`.post-list`, `overflow-y: auto`)이나 게시물 상세 모달(`.modal-panel`, `overflow: auto`) 안에서 열면 그 조상의 스크롤 영역 경계에서 잘려 보였습니다("왼쪽에 뜨면서 div 밖으로 벗어나서 가려짐" — CSS 스펙상 `overflow-y`만 `auto`로 줘도 `overflow-x`가 자동으로 `auto`가 되어 가로로도 같이 잘립니다). 트리거의 `getBoundingClientRect()`로 뷰포트 좌표를 직접 계산해 `document.body`에 포털로 그리면 어떤 조상의 `overflow`와도 무관해집니다 — `pad-canvas.tsx`의 `DragOverlay`(드래그 미리보기)가 같은 `.post-list` 클리핑 문제를 이미 같은 방식으로 풀어둔 것과 동일한 이유입니다. 위치는 스크롤·리사이즈 시 다시 계산하고, 위쪽 공간이 부족하면(`rect.top`이 메뉴 높이보다 작으면) 아래로 열립니다.
- `SINGLE` 정책에서는 새 반응을 누르면 기존 반응을 대체하고, `MULTIPLE` 정책에서는 이모지별로 독립 토글합니다.
- 서버 응답 전에는 낙관적으로 집계를 바꾸고 요청 실패 시 원래 상태로 되돌립니다. 낙관 상태가 기준으로 삼은 집계·사용자 반응 스냅샷과 새 props가 달라지면 SSE 또는 상위 상태의 최신 서버 값을 우선합니다.
- UI 타입과 기본 반응 메타데이터는 `lib/reactions/types.ts`의 서버 공통 계약을 재사용합니다.
- `lib/reactions/validation.ts`가 기본 allowlist 또는 `EMOJI:<한 개의 grapheme>` 형식을 검증합니다. ZWJ 가족·직업, 국기, 키캡은 허용하지만 일반 문자와 복수 이모지는 거부합니다.
- API는 로그인·보드 접근·반응 허용 여부·사용자별 정책·이모지 길이를 다시 검증해야 합니다.
- 집계가 바뀌면 보드 SSE는 전체 보드 데이터를 다시 보내지 않고 게시물 ID와 반응별 집계만 전달합니다.

현재 `ReactionType.LIKE` 데이터는 다중 반응 마이그레이션에서 `LIKE` 키로 보존해야 합니다.
