# pyxis 보드 컴포넌트 개요

이 폴더는 보드 캔버스, 섹션, 게시물 카드·상세·작성 UI와 SSE 클라이언트 상태를 담당합니다.

`post-card-actions.tsx`는 게시글 카드 오른쪽 위 `…` 메뉴와 패드 전체가 공유하는 편집기를 제공합니다.
`editAnyPost` 또는 `editOwnContent && isMine`일 때 수정·삭제를 표시하고, 삭제 전용 운영 권한
`deleteAnyPost`에는 삭제만 표시합니다. 동결·예약 동결 상태에서는 숨깁니다. 손님 본인 여부도
서버가 내려준 `isMine`을 사용합니다. 삭제 확인 중 권한이 바뀌면 실행을
중단하고, 최종 권한·비밀번호·동결 검사는 기존 게시물 API가 다시 수행합니다. 공용 카드 메뉴와
작성기는 body 포털로 열어 카드의 overflow/content-visibility에 잘리지 않습니다. 메뉴의 포인터와
클릭은 카드 드래그·상세 탐색으로 전파되지 않습니다. 편집 시작 시 본문·버전을 고정해 동시 수정으로
초안이 덮이지 않고 기존 409 충돌 검사가 유지됩니다. 저장·삭제 뒤 해당 카드만 갱신해 더 불러온
페이지를 보존하며, 삭제 응답과 SSE는 같은 중복 방지 경로로 처리해 섹션 개수를 한 번만 차감합니다.
휴지통 복구(`post.updated`)와 재연결 후 추가 페이지에서 복구 글을 받는 경우에는 재삭제를 허용합니다.
첨부는 글 버전과 별도로 변하므로 편집 중 수신한 첨부 델타를 뒤늦은 저장 응답보다 우선합니다.

`post-composer.tsx`의 첨부 입력은 파일 선택, 드래그앤드롭, 클립보드 이미지 붙여넣기를 같은 검증·중복 제거 경로로 처리합니다. 지원 형식과 파일당 30MB 제한을 클라이언트에서 먼저 안내하고, 사용자는 업로드 전에 목록에서 개별 파일을 제거할 수 있습니다. 붙여넣기는 클립보드가 파일만 담고 있을 때만 첨부로 처리합니다. 일부 앱이 텍스트·HTML과 함께 렌더링된 WebP를 제공하더라도 텍스트 입력을 우선하므로 코드나 서식 있는 글을 붙여넣을 때 보조 이미지가 첨부되지 않습니다. 최종 파일 검증과 WebP 변환은 서버 첨부 API가 다시 수행합니다.

`pad-access-gate.tsx`는 인증된 비멤버에게 권한 획득 절차와 요청 버튼을 제공하고, `pad-access-requests.tsx`는 소유자·관리자의 설정 모달에서 대기 요청 승인·거절을 처리합니다.

`pad-trash.tsx`는 서버가 사용자별로 필터링한 숨김 섹션·글·댓글을 7일 안에 복구하는 보관함 UI입니다. 첨부파일은 삭제 즉시 영구 정리되어 보관함에 나오지 않습니다. 개별 영구 삭제 외에도 현재 보이는 종류가 다른 항목을 모두 선택해 한꺼번에 영구 삭제할 수 있으며, 서버는 모든 항목의 패드 소속·숨김 상태·항목별 권한을 먼저 검증합니다.

`pad-sections-board.tsx`의 드래그앤드롭: 섹션은 하나의 `SortableContext`(가로) 안에 있어 드래그 중 재배치가 dnd-kit 기본 동작만으로 자연스럽습니다. `section-board-collision.ts`는 섹션을 옮길 때 내부 게시물을 충돌 후보에서 제외해, 게시물 목록을 끝까지 스크롤한 상태에서도 중첩된 카드가 섹션 드롭을 가로채지 못하게 합니다. 게시물은 섹션마다 별도의 `SortableContext`(세로)라 다른 섹션으로 넘어갈 때는 `onDragOver`에서 `localSections`를 직접 옮겨줘야 드래그 도중 다른 카드들이 자리를 비켜주는 것처럼 보입니다. `onDragEnd`는 이미 옮겨진 컨테이너 안에서 최종 순서만 확정해 `/api/posts/[postId]/reorder`를 호출합니다. dnd-kit이 섹션 간 이동 뒤 움직인 카드 자체를 `over`로 돌려주는 경우도 서버에 저장하며, 취소·실패 때는 시작 당시 배열 전체를 덮지 않고 그 카드만 원래 이웃 사이로 돌려 드래그 중 들어온 새 글 SSE를 보존합니다.

`use-board-drag-auto-scroll.ts`는 편집기 목록 드래그와 같은 가장자리 기반 RAF 스크롤을 섹션 보드의 중첩 구조에 맞게 적용합니다. 포인터가 화면 좌우 가장자리에 있으면 `.pad-canvas`를, 위아래 가장자리에 있으면 포인터 아래 또는 가장 가까운 섹션의 `.post-list`를 움직여 두 축을 동시에 스크롤할 수 있습니다. 포인터 드래그 중에는 dnd-kit 기본 자동 스크롤과 가로 scroll snap을 잠시 꺼 경쟁을 막고, 키보드 드래그에는 기존 dnd-kit 처리를 유지합니다.

저장 성공 뒤 낙관적 배열을 바로 지우지 않습니다. `reconcile-sections.ts`의 `applyBoardEventDelta`가 요청을 보낸 본인을 포함한 새 글·수정·삭제·이동, 댓글·첨부·반응, 섹션 이벤트를 `liveData.board.sections`에 바로 적용하고, 드래그 중이면 같은 델타를 낙관 배열에도 합칩니다. 따라서 다른 사람이 글을 쓰는 동시에 섹션을 옮겨도 전체 RSC 응답이 낙관 배열을 과거 위치로 되돌리지 않습니다. 본인이 정렬 방식·레이아웃·새 글 위치를 바꿨을 때만 이전 수동 배열을 버립니다. SSE 재연결 시에는 활동 기록이 없는 재정렬도 놓쳤을 수 있으므로 `/api/boards/[boardId]/realtime-snapshot` JSON 정본을 한 번 받습니다.

`.post-list`(섹션 내부 스크롤 영역)는 `overflow-y: auto`라, `useSortable`의 transform만으로 카드를 옮기면 다른 섹션으로 넘어가는 동안 카드가 원래 섹션의 스크롤 박스 경계에 시각적으로 잘려 "갇혀 있는" 것처럼 보였습니다. 그래서 `DndContext`에 `DragOverlay`를 추가해, 드래그 중인 카드/섹션은 포털로 최상위에 떠 있는 `PostDragPreview`/`SectionDragPreview` 복제본으로 그리고, 원래 자리의 카드는 `.dragging` 클래스(옅은 투명도)로만 남겨둡니다.

`pad-canvas.tsx`의 게시물 목록은 섹션마다 첫 30개만 SSR로 받고, `section-column.tsx`의 "더 보기"가 `GET /api/sections/[sectionId]/posts` cursor 페이지를 이어 붙입니다. `totalPostCount`는 아직 받지 않은 카드까지 포함한 전체 개수이고 `nextCursor`가 남아 있으면 해당 섹션에 뒷페이지가 있다는 뜻입니다. 검색은 현재 받은 카드의 제목·본문을 즉시 걸러내며, 뒷페이지가 있으면 검색 범위를 화면에 안내합니다. 보이지 않는 이웃을 모르는 상태에서 잘못된 position을 저장하지 않도록 모든 페이지를 받을 때까지 게시물 수동 드래그는 비활성화합니다.

전체 카드는 검색·SSE 병합·드래그 순서를 위해 DOM에 유지하되 `.post-card`에 `content-visibility: auto`와 기억형 intrinsic block size를 적용합니다. 브라우저는 화면에서 떨어진 카드의 자식 레이아웃·페인트를 건너뛰고, 가까워지면 실제 높이를 계산해 이후 placeholder 크기로 기억합니다. 커버 이미지는 별도로 `loading="lazy"`를 사용합니다. 실제 드래그 카드와 `DragOverlay`는 `content-visibility: visible`로 강제해 dnd-kit 측정과 미리보기가 생략되지 않습니다. 이 방식은 IntersectionObserver로 카드를 DOM에서 제거하는 가상화와 달리 전체 sortable item을 유지하므로 키보드 탐색과 섹션 간 드래그를 깨뜨리지 않습니다.

검색과 글 추가는 화면 크기와 무관하게 우측 하단의 반투명 플로팅 액션 두 개(`.board-mobile-controls` — 이름의 mobile은 모바일 전용이던 시절의 흔적)가 담당합니다. 예전의 상단 도구행(검색창·드래그 안내·섹션 추가 버튼)과 데스크톱 전용 글 추가 버튼은 상단 영역 높이를 줄이는 개편에서 제거했습니다. SECTIONS 레이아웃에서는 가로 스크롤로 가장 가까워진 섹션을 자동 추적해 그 섹션에 글을 쓰고, 모바일(720px 이하)은 각 섹션의 큰 글 추가 버튼도 숨겨 캔버스 세로 공간을 확보합니다. 다른 레이아웃에 섹션이 여러 개면 작은 섹션 선택 팝오버를 먼저 엽니다. 섹션 생성은 상단 `⋯` 메뉴와 SECTIONS 캔버스 가장 오른쪽의 `새 섹션` 카드를 함께 제공합니다. 모바일에서도 일반 가로 스크롤과 스냅으로 이 카드까지 이동할 수 있으며, 섹션이 하나도 없을 때는 관리자의 첫 화면에 이 카드가 바로 나타납니다.

`pad-share-panel.tsx`는 보드 상단 "공유" 버튼이 여는 전달 전용 모달입니다. 원주소 복사와 `qrcode` 패키지로 클라이언트에서 직접 생성하는 QR 코드를 보여주고, 설정 관리 권한이 있으면 공용 `ShortLinkManager`로 사람이 입력할 `/go/{slug}` 별칭도 생성·변경·복사·삭제합니다. 발견 범위·비밀번호·iframe 삽입은 이 모달에 두지 않습니다. 발견 범위와 비밀번호는 설정의 `settings/pad-sharing-settings.tsx`, 접근 요청과 초대 링크는 같은 `공개·공유` 탭에서 관리합니다. 비밀번호 입력을 비워 저장하면 기존 값을 유지하고 해제는 별도 버튼으로 수행하며, AES-GCM 암호화본이 있는 현재 비밀번호는 패드 소유자만 `/api/boards/[boardId]/password`에서 다시 확인할 수 있습니다. `pad-password-gate.tsx`는 비밀번호가 걸린 보드에 비멤버 방문자가 들어왔을 때 보여주는 입력 화면입니다(`app/b/[slug]/page.tsx`의 `password-required` 상태).

별도로 열리던 게시물 `승인 대기함` 메뉴와 모달은 접근 요청 관리와 혼동된다는 피드백으로 제거했습니다. 서버의 게시물 검토 API는 기존 데이터와 직접 호출 호환성을 위해 유지합니다.

`pad-activity-panel.tsx`는 Prisma의 `BoardActivityType`을 그대로 DTO 타입과 아이콘 맵의 키로 사용합니다. 게시물 생성·수정·삭제·승인 처리(`POST_MODERATED`), 댓글 작성, 멤버 참여, 접근 요청 처리를 모두 표시하며, enum에 새 값이 추가됐는데 아이콘을 빠뜨리면 TypeScript 검사에서 실패하도록 `Record`로 완전성을 확인합니다. 배포 전환 중 예상하지 못한 활동 값이 들어와도 패널 전체가 깨지지 않도록 기본 아이콘도 둡니다.

보드 동결은 서버 페이지가 요청 시 계산한 `initialFrozen`을 첫 화면 정본으로 쓰고, `pad-canvas.tsx`가 미래의 `freezeAt`까지 남은 시간에 타이머를 걸어 열린 화면도 예약 시각에 배너와 쓰기 차단 상태로 전환합니다. 서버(`isBoardFrozen`, `lib/auth/authorization.ts`)도 `Board.state === "FROZEN"` 또는 `freezeAt <= now`를 판정하므로 실제 API 차단과 일치합니다. `freezeAt`은 크론 없이 매 쓰기 요청 시점에도 다시 평가되어, 탭 타이머가 지연되더라도 서버 쓰기는 통과하지 않습니다. 동결 해제 버튼은 `state: "ACTIVE"`와 함께 `freezeAt: null`도 보내 지나간 예약이 남아 즉시 다시 동결로 판정되는 것을 막습니다.

`post-composer.tsx`는 padupgrade.md 6.1~6.3 작성 흐름을 통합합니다. 보드의 새 글 작성은 데스크톱 우측 패널로 열리고 모바일에서는 `visualViewport`를 따라가는 전체화면으로 전환되어 소프트 키보드 바로 위에 첨부 도구 막대를 유지합니다. 단독 게시물 페이지의 수정은 같은 컴포넌트의 인라인 표시를 사용해 게시물 영역 전체를 편집기로 바꾸고 댓글 영역은 유지합니다. 본문은 `composer/markdown-editor.tsx`의 Milkdown CommonMark 편집기를 사용해 백틱 인라인 코드, 제목, 인용, 목록, 코드 블록을 입력 즉시 시각화하지만 초안·API·DB에는 계속 Markdown 문자열을 저장합니다. 초안 복구처럼 외부 값이 바뀔 때만 편집기 문서를 교체해 일반 입력의 커서와 실행 취소 기록을 보존합니다. 파일·이미지·촬영/녹음·드래그앤드롭·이미지 붙여넣기는 같은 검증 큐로 연결되고 추가 순간 현재 커서에 상대 경로형 전용 Markdown 블록을 자동 삽입합니다. 저장 뒤 실제 첨부 ID로 확정하므로 한 글에 여러 이미지·파일을 문단 사이에 섞을 수 있고, 기존 첨부와 링크는 목록의 배치 버튼으로 같은 위치 삽입을 사용합니다. 배치하지 않은 첨부와 이 문법이 없던 과거 첨부는 상세 본문 위에 표시합니다. `usePostDraft`가 제목·본문을 로컬에 자동저장하고 복구·이탈 경고를 제공하지만 상시 자동저장 안내는 표시하지 않습니다. 본문 저장 뒤 `useAttachmentUploadQueue`가 파일별 진행률·취소·재시도와 최대 3개 동시 업로드를 처리합니다. 성공한 파일은 다시 올리지 않고 실패 항목과 실패 링크만 남기므로 게시물 본문을 보존한 채 재시도할 수 있습니다. `LinkPreviewInput`은 여러 URL을 줄 단위로 받아 최대 3개씩 미리보기를 확인하고 중복·전체 첨부 20개 한도를 적용한 다음, 대기 목록의 링크를 게시물 수정 또는 작성 한 번으로 저장합니다. 링크의 검증된 대표 이미지도 이때 함께 저장해 패드 카드와 상세 화면이 제목·출처 호스트가 있는 같은 링크 카드 디자인을 사용합니다.

`settings/`의 게시물 필드 디자이너는 제목·본문·첨부 표시/필수/placeholder와 사용자 정의 필드의 종류·선택지·순서·버전을 관리합니다. 작성기는 현재 설정 버전을 함께 제출하고, 카드·상세·Table 레이아웃은 게시 당시 고정된 사용자 정의 값을 표시합니다. 외형 설정은 레이아웃, 수동/작성일/제목/무작위 정렬, 새 글 위치, 카드 크기, 배경색·강조색, 글꼴, 작성자·시각 표시를 관리합니다. 기본 정보의 배경 이미지 필드는 전용 업로드 API로 JPG·PNG·WebP를 WebP로 변환해 저장하며, `pad-canvas.tsx`가 이 이미지를 SECTIONS를 포함한 모든 레이아웃의 패드 페이지 배경에 공통 적용합니다. 개별 레이아웃 surface에는 배경을 다시 그리지 않아 같은 이미지가 이중으로 반복되지 않습니다.

`comments/`는 게시물의 댓글·멘션·수정·삭제와 이미지·음성·PDF 첨부를 담당합니다. 화면 안에 계속 중첩되는 대댓글 폼은 모바일 레이아웃과 대화 흐름을 깨뜨려 제거했고, 새 댓글은 모두 시간순의 한 대화로 표시합니다. 기존 `parentId` 데이터와 API 입력은 호환을 위해 유지하되 옛 답글도 평면 목록에서 빠짐없이 보여줍니다. 댓글의 `언급하여 답장`은 하단의 단일 작성기로 이동해 작성자 토큰을 채우며, 사용자가 직접 `@` 뒤에 이름을 입력해도 패드 멤버·기존 댓글 작성자를 최대 6명까지 좁혀 찾습니다. 선택한 내부 사용자 ID만 `CommentMention`으로 저장하므로 같은 이름이나 표시 문자열만으로 알림 대상을 추측하지 않습니다. 참여자 전원을 나열하던 하단 `@` 칩은 제거했습니다. 댓글 응답은 작성자가 현재 활성 상태인지 `mentionable`로만 알려주고, 자동완성은 비활성 작성자를 제외합니다. 서버도 `mentionedUserIds`가 `ACTIVE` 사용자인지 다시 확인하므로 과거 댓글에 남은 삭제 계정은 멘션할 수 없습니다. 본문은 HTML로 해석하지 않고 HTTP(S) 주소만 안전한 새 탭 링크로 승격합니다.

상세 페이지 댓글 작성기는 멘션 자동완성과 글자 수가 있는 독립 영역으로 유지합니다. 패드 카드의 데스크톱 빠른 입력은 무테 전체 폭 입력면 안에 클립·전송 아이콘을 넣고 내용에 따라 높이가 늘어납니다. 모바일 카드는 `댓글 남기기` 버튼으로 약 155px 높이의 하단 시트를 열며 파일·사진·음성·전송 도구를 제공합니다. 시트는 게시물 작성기와 같은 `visualViewport` 높이·상단 오프셋을 사용해 소프트 키보드 바로 위에 붙고, 입력이 길어지면 최대 높이까지 확장됩니다. `COMMENT_MENTIONED` 알림에는 `postId`와 `commentId`가 함께 저장되며 알림을 누르면 독립 게시물 경로의 `#comment-{id}`로 이동해 대상 댓글을 스크롤하고 강조합니다.

`reactions/`는 기본 반응과 한 grapheme 이모지, 단일/복수 정책을 표시하며 API가 반환한 키별 집계로 낙관 상태를 교정합니다. SSE `reaction.changed` 이벤트는 전체 보드를 다시 조회하지 않고 해당 게시물의 집계만 로컬로 교체합니다.

`comment-attachment-rules.ts`는 카드와 상세 댓글의 파일 판정·중복 제거·4개 제한을 공유합니다. 로그인 사용자는 이미지·음성·PDF를, 손님은 이미지만 추가할 수 있고 MIME의 코덱 파라미터와 확장자를 함께 판정해 `audio/webm;codecs=opus` 녹음도 정상 수용합니다. 모바일 음성 버튼은 `MediaCapture`의 audio 모드만 지연 로딩합니다. 댓글을 먼저 저장한 뒤 첨부를 올리므로 일부 파일이 실패해도 댓글은 보존하고 실패 파일명만 알립니다. 성공한 댓글 첨부는 카드 초기 DTO와 생성·수정·삭제 SSE 델타에 포함되어 새로고침 없이 동기화됩니다.

`MediaCapture`는 권한 프롬프트가 열린 동안 패널을 닫거나 모드를 바꾼 경우, 늦게 성공한 `getUserMedia()`의 세대 번호를 검사해 새 `MediaStream` 트랙을 즉시 정지합니다. 이미 ref에 들어온 트랙·녹화기도 언마운트 정리에서 멈춥니다. `HwpViewer`는 문서 전환/닫기 때 진행 중인 대용량 fetch를 `AbortController`로 취소하고, WASM 로드 실패 Promise를 영구 캐시하지 않습니다. 페이지별 IntersectionObserver·타이머·Blob URL과 WASM 객체 해제 규칙은 그대로 유지합니다.

`layouts/`에는 Columns·Wall·Grid·Stream·Timeline·Table 렌더러가 있습니다. 현재 `SECTIONS`는 기존 dnd-kit 섹션/게시물 편집 흐름을 계속 사용하고, 나머지 형식은 `PadLayoutRenderer`를 통해 같은 게시물 데이터를 다른 배치로 읽습니다. 자동 정렬과 검색 중에는 드래그를 비활성화해 화면 순서와 저장 순서가 충돌하지 않게 합니다.

`pad-export-panel.tsx`는 보드 상단의 내보내기·발표 모달입니다. 읽기 권한이 있는 사용자에게 인쇄·발표 링크를, 보드 소유자·관리자에게만 CSV·XLSX·첨부 ZIP 작업을 보여줍니다. `export/`는 인쇄용 게시물 뷰, 브라우저 PDF 인쇄·PNG 캡처 액션, 키보드와 버튼으로 이동하는 발표 화면을 담당합니다. 실제 다운로드 Route Handler가 같은 권한을 다시 검사하므로 클라이언트 노출 조건은 권한 경계가 아닙니다.

## 보드 상단바 정리 (사용자 UX 피드백 반영)

980px 이하에서도 제목 영역의 최대 폭을 배정된 그리드 칸의 100%로 제한합니다. 확대·축소로
반응형 경계를 오갈 때 긴 제목이 문서 전체 폭을 늘리지 않으며, 제목 안쪽 스크롤과 섹션 캔버스의
가로 스크롤은 유지됩니다. 상단바를 잘라 숨기지 않으므로 더보기 드롭다운도 그대로 열립니다.

기능이 하나씩 추가될 때마다 `pad-canvas.tsx` 상단바에 아이콘이 하나씩 늘어나(활동·즐겨찾기·공유·내보내기·보관함·설정 등) 모바일에서 아이콘으로 가득 차고, "무슨 아이콘이 무슨 기능인지 모르겠다"는 사용성 피드백을 받았습니다. 두 가지로 정리했습니다.

- 보드의 별표는 홈과 똑같은 `BoardFavorite`/`/favorite` API를 사용하고 문구도 `즐겨찾기 추가·해제`로 통일했습니다. 최초 즐겨찾기 여부는 `getBoardPageData()`가 보드와 함께 읽고, 클릭 mutation만 `/favorite` API를 사용합니다. 활동 타임라인의 읽음 추적용 `BoardFollow`는 별개의 내부 모델이며 별표 UI로 노출하지 않습니다.
- `pad-more-menu.tsx`는 자주 안 쓰는 보조 기능(보드 활동 기록, 즐겨찾기, 새 섹션, 보관함, 내보내기·발표)을 "⋯" 버튼 하나의 드롭다운으로 묶습니다. `notification-bell.tsx`와 같은 클릭 바깥 감지 패턴을 그대로 씁니다. 항목은 `{key, label, icon, onClick}` 배열로 받으므로 보드 관련 로직은 전혀 모르고, 어떤 항목을 보여줄지는 `pad-canvas.tsx`가 `capabilities`·로그인 여부로 결정합니다.
- 상단바에 항상 보이는 것은 이제 동기화 상태, 다크모드 토글, 알림 벨, 공유 버튼, 더보기(⋯), 설정(관리자만) 6개뿐입니다.
- 검색·글 추가는 화면 크기와 무관하게 우측 하단 반투명 플로팅 액션 두 개로 옮겼습니다(원래 모바일 전용이던 패턴을 전 화면으로 확대하며 상단 도구행은 제거). 글 추가는 현재 보이는 섹션을 대상으로 하므로 모바일에서 섹션마다 큰 `+` 버튼을 반복하지 않습니다.

보드 설정 모달을 기능별 탭으로 나눈 내용은 `settings/overview.md`를 참고하세요.

## 섹션 "글 추가" 버튼 위치, 보드 소개 압축 (사용자 UX 피드백 반영)

- `section-column.tsx`의 데스크톱 "글 추가" 버튼(`.section-add-trigger`)은 헤더 바로 아래에 유지하고 보드 강조색을 따릅니다. 모바일에서는 같은 버튼이 섹션마다 세로 공간을 반복해서 차지하므로 숨기고, 현재 보이는 섹션을 추적하는 공용 플로팅 글 추가 버튼 하나로 대체합니다.
- 같은 헤더의 섹션 이동 손잡이(드래그 핸들)는 예전에 헤더 위에 따로 뜬 채(`position:absolute`) 세로 공간을 차지했는데, "⋯" 메뉴 버튼 옆 `.section-header-actions`로 옮겨 한 줄에 모았습니다.
- 섹션 제목에 더블클릭하면(`onDoubleClick`, 관리 권한 있을 때만) 기존 "⋯ → 수정"과 같은 편집 모달이 열립니다 — 더 빠른 진입점을 하나 더 추가한 것이고, 기존 메뉴 경로도 그대로 남아 있습니다. 섹션 설명은 이 레이아웃 헤더에서 더 이상 보여주지 않습니다("설명이 너무 길다"는 피드백) — 데이터는 계속 저장되고 편집 화면에서는 그대로 바꿀 수 있습니다.
- `pad-canvas.tsx`의 보드 소개 영역(`.board-hero`)은 한 줄로 압축했다가, 그래도 글 내용이 아닌 상단 영역이 padlet 대비 2배 이상 높다는 피드백으로 **아예 삭제**했습니다. 제목·발견 범위·제작자는 상단바 가운데(`.board-nav-center`)로 이동: 발견 범위는 텍스트 라벨 없이 아이콘만(비공개 `LockKeyhole`/링크 공개 `Link2`/전체 공개 `Globe2`, 라벨은 `title`·`aria-label` 툴팁), 제목은 진하게(`--ink`, 750), 제작자는 작은 회색 글자로 표시합니다. 제목이 길면 말줄임 대신 이 영역 안에서만 가로 스크롤합니다(스크롤바 숨김). 멤버 아바타·"N명이 함께해요"와 운영중/동결됨 상태 배지는 화면에서 뺐습니다(멤버는 공유 패널·설정에서, 동결은 상단 배너로 확인). 설명(`board.description`)은 계속 화면에 표시하지 않고 `app/b/[slug]/page.tsx`의 `generateMetadata`가 `<meta name="description">`에만 내려주며, `.board-nav-center`의 `title` 속성으로 마우스 오버 시 볼 수 있습니다. 제목 더블클릭으로 패드 설정을 여는 진입점은 상단바 제목으로 이어받았습니다. 모바일에서는 원래 상단바 가운데를 숨기고 hero가 제목을 보여줬는데, 이제 상단바 가운데가 유일한 제목 표시처라 모바일에서도 유지하고 공유 버튼 라벨(`.board-toolbar-label`)은 숨겨 아이콘만 남깁니다. 헤더가 낮아진 만큼 `.section-column` 높이 계산(`100dvh - …`)도 함께 보정했습니다.

## 상단 영역 축소 2차 — 도구 줄 제거, 섹션 헤더 압축 (사용자 UX 피드백 반영)

"글 내용이 아닌 상단 영역이 padlet 대비 2배 이상"이라는 피드백의 후속으로, hero·섹션 필 삭제에 이어:

- 상단 도구 줄(`.board-tools`: 검색창 + 드래그 안내 문구 + 비SECTIONS 빠른 추가 select + 섹션 추가 버튼)을 통째로 제거했습니다. 검색·글 추가는 기존 모바일 플로팅 컨트롤을 전 화면 공용으로 승격(데스크톱 42/48px, 모바일 38/40px), 섹션 추가는 "더보기" 메뉴의 `새 섹션 만들기`와 캔버스 끝의 `새 섹션` 카드가 담당합니다. 비SECTIONS 레이아웃의 대상 섹션 선택은 플로팅 추가 버튼의 섹션 선택 팝업이 이어받습니다(관련 스타일을 720px 미디어쿼리에서 기본 스타일로 승격). 검색창의 `⌘K` 표시는 실제 핸들러가 없는 장식이어서 기능 손실이 없습니다.
- `.section-header`는 min-height 62→46px, 패딩 축소, `align-items: flex-start`→`center`로 바꿨습니다 — 제목 h2와 "⋯" 버튼의 세로 중심이 어긋나 보이던 문제도 이것으로 해결(개수 배지의 margin-top 보정도 함께 제거).
- 모바일 섹션 칼럼 폭은 86vw(390px 화면에서 335px)가 데스크톱(256px)보다 넓다는 피드백으로 `min(86vw, 272px)`로 상한을 둬, 다음 섹션이 옆에 살짝 보입니다.
- 헤더가 낮아진 만큼 `.section-column`의 `100dvh` 높이 계산을 데스크톱·980px·720px 모두 보정했습니다.
- **섹션 박스 해체**: `.section-column`은 더 이상 테두리·배경·그림자가 있는 큰 카드가 아니라 투명한 세로 레인입니다 — 박스+안쪽 패딩(`.post-list` 12px)이 카드 가로폭을 256px 중 26px이나 잡아먹는 게 문제였습니다(사용자 제안). `.section-header`만 전체 라운드의 독립 카드로 남고(섹션 드래그 오버레이의 그림자도 헤더가 담당), 게시물 카드·글 추가 버튼·빈 상태는 컬럼 폭 100%를 씁니다. 컬럼끼리 시각적 구분은 캔버스 gap(18px)과 헤더 카드가 담당합니다.

## 게시물 독립 상세 라우트

카드를 클릭했을 때 열리던 오른쪽 모달은 폭 규칙이 서로 충돌하고, 긴 본문과 댓글이 한 패널 안에서 경쟁해 읽기 흐름도 좋지 않았습니다. 상세 화면을 `/b/{slug}/posts/{postId}` 독립 경로로 옮겼습니다.

- `post-card.tsx`는 카드 클릭과 키보드 Enter/Space를 새 경로로 연결합니다. 드래그 직후의 click 차단과 카드 안 반응 버튼의 독립 동작은 유지합니다. 본문을 평문 요약으로 만들지 않고 `PostBody`로 렌더링하므로 제목 크기·목록과 문단 사이 첨부가 상세 화면과 일치합니다. 다만 코드 블록은 목록 스크롤을 방해하지 않도록 첫 줄만 카드 너비 안에서 `...` 말줄임으로 표시하고 내부 스크롤은 만들지 않습니다. 오른쪽의 작은 복사 아이콘은 미리보기가 아니라 원래 코드 전체를 복사합니다. 본문에 배치하지 않은 첨부 중 첫 시각 자료가 이미지면 기존 파일 썸네일을 사용합니다. 링크면 YouTube의 고정 썸네일 또는 일반 웹의 저장된 대표 이미지를 16:9 커버로 쓰고, 이미지 위에 링크 제목과 `youtube.com` 같은 호스트를 표시합니다. YouTube 카드에는 재생 표시도 함께 둡니다.
- 단독 게시물의 본문 미배치 첨부가 둘 이상이고 편집 권한이 있으면 각 항목 왼쪽에 드래그 손잡이를 표시합니다. 드롭 순서는 `/api/posts/[postId]/attachments/reorder`에 전체 첨부 ID로 저장하되 본문 배치 첨부의 기존 슬롯은 유지하며, 요청 실패 시 이전 순서로 되돌리고 오류를 댓글 패널 아래에 표시합니다.
- 한글 slug는 `useParams()`에서 이미 `%EC...`로 들어오므로 그대로 다시 `encodeURIComponent`하지
  않습니다. `lib/board/route-paths.ts`가 입력을 정규화한 뒤 정확히 한 번만 인코딩해 `%25EC...`
  이중 인코딩과 그에 따른 상세 페이지 404를 방지합니다.
- `post-detail.tsx`의 `PostDetailPage`는 본문·사용자 정의 필드·첨부·반응·댓글·수정·삭제를 페이지형 UI로 제공합니다. 상단 nav는 패드 이동·테마 같은 페이지 전역 동작만 두고, 게시물 수정·삭제 메뉴는 제목 영역 오른쪽 위에 배치합니다. 수정할 때 별도 우측 작성 패널을 띄우지 않고 왼쪽 게시물 영역 자체를 전체 너비 인라인 `PostComposer`로 전환하며 댓글 영역은 유지합니다. 전용 본문 블록이 없는 첨부는 글보다 먼저 보여 주고, 블록이 있는 첨부는 해당 문단 사이에서 렌더링합니다. 데스크톱은 본문과 댓글의 2단 구성, 900px 이하는 본문 다음 댓글로 이어지는 1단 구성입니다. 댓글 API는 최신 20개부터 가져오고 “이전 댓글 더 보기”로 과거 대화를 앞쪽에 붙여, 새 멘션 알림의 대상이 첫 화면에서 빠지는 일을 줄입니다.
- 상세 서버 페이지는 `getBoardPageData(..., { focusPostId })`를 사용해 보드와 같은 공개 범위·비밀번호·멤버·게시 상태 권한을 적용하면서 해당 게시물만 조회합니다.
- 수정은 기존 `PostComposer`를 열고, 삭제가 끝나면 원래 패드 경로로 이동합니다.

세부 라우팅과 권한 설명은 `app/(play)/b/[slug]/posts/[postId]/overview.md`를 참고하세요.

## 전체 글자 크기 확대, 섹션 컬럼 너비 축소 (사용자 UX 피드백 반영)

"전체적인 픽셀 크기가 너무 작다. 패들렛은 기본 14px인데 여긴 11px다"라는 피드백과 "열 가로 너비가 너무 넓다, 256 정도면 적당하다"는 피드백을 받아 반영했습니다.

- **글자 크기**: `app/globals.css`와 board 하위 각 컴포넌트의 `.module.css`(댓글, 반응, 첨부, 설정, 레이아웃, 작성기 등)에 있는 `font-size` 선언을 7~20px 구간에서 **약 1.27배(11px → 14px가 사용자가 준 정확한 기준점)** 비례 확대했습니다. 인쇄물/발표 화면 전용 스타일(`export/pad-print-view.module.css`, `export/pad-presentation.module.css`)은 종이 크기·슬라이드 비율에 맞춰 이미 별도로 튜닝돼 있어 이번 확대에서 제외했습니다. 22px 이상(홈 마케팅 히어로, 관리자 패널 제목 등)은 이미 충분히 크고 "기본 글자가 작다"는 피드백과 무관해 손대지 않았습니다.
- **섹션 컬럼 너비**: `.section-column`을 326px → 256px로 줄였습니다(`add-section-card`의 230px보다 살짝 넓은 정도로, 화면에 더 많은 섹션이 한 번에 보입니다).
- **섹션 헤더 재압축**: 숫자 인덱스(`01`, `02`…)는 정보 가치가 낮아 제거했습니다. 제목은 헤더 첫 줄에서 한 줄 말줄임으로 표시하고 전체 제목은 기존 편집 진입점의 `title` 속성으로 확인할 수 있어, 모바일에서 각 컬럼의 본문 높이를 더 확보합니다.
- 나머지 한 줄 말줄임 요소들(상단 유저 알약, 보드 소개 한 줄, 설정 목록의 이름·이메일 등)은 원래도 "너무 길면 잘라내는" 목록형 UI라 글자가 커져 조금 더 일찍 잘리는 것 자체는 의도된 동작이라 그대로 뒀습니다.

변경한 경로: `app/globals.css` 및 `components/`, `components/pad/` 아래 대부분의 `.module.css` (export/ 인쇄·발표 스타일 제외)

## 카드/섹션 아무 데나 길게 눌러 드래그, 담벼락·격자 순서 변경 지원 (사용자 UX 피드백 반영)

안내 문구는 "카드를 길게 눌러 순서를 바꿀 수 있어요"였는데 실제로는 카드 오른쪽 아래 작은 그립 아이콘 버튼만 드래그 시작점이라 문구와 동작이 어긋났습니다. 문구를 실제 동작에 맞춘 게 아니라 반대로 동작을 문구에 맞췄습니다.

- `sortable-post-card.tsx`: `useSortable`의 `listeners`/`attributes`를 기본 `PostCard`에 주입해 `<article>` 전체를 드래그 시작점으로 만듭니다. `listeners`에서 `onKeyDown`만 따로 떼어 시각적으로 숨긴(`.drag-handle`, 키보드 포커스 시에만 보임) span에 붙여, 카드에 포커스가 있을 때 Enter/Space가 "글 열기"와 dnd-kit의 "키보드 드래그 시작"으로 충돌하지 않게 분리했습니다. 드래그 직후 뒤따라오는 클릭이 곧바로 상세 페이지를 열어버리지 않도록 `wasDraggingRef`로 한 번 걸러냅니다.
- 마우스는 8px 이동(`MouseSensor`), 터치는 250ms 누르고 있어야(`TouchSensor`, `delay`+`tolerance`) 드래그가 시작되도록 센서를 분리했습니다(예전엔 `PointerSensor` 하나로 거리 8px만 봤음). 터치에서 거리 기준을 쓰면 스크롤하려는 손가락도 드래그로 잡혀버리는데, 지연 기준은 그 시간 동안 손가락이 tolerance 이상 움직이면 드래그를 취소하고 기본 스크롤에 넘겨줍니다.
- `section-column.tsx`의 섹션(열) 이동도 같은 방식으로 바꿨습니다 — 헤더 전체가 드래그 대상이고, 그립 아이콘은 키보드 포커스 전용으로 숨겼습니다. 섹션을 드래그할 때 뜨는 `SectionDragPreview`(`pad-sections-board.tsx`)는 원래부터 섹션 헤더만(안의 게시물 카드 전부가 아니라) 복제해서 커서를 따라다니게 했었습니다.
- **다른 섹션으로 게시물을 옮기는 무한루프 버그**: 예전엔 좁은 그립 버튼으로 다른 섹션까지 정확히 끌고 가기 어려워 거의 재현이 안 됐는데, 카드 전체를 눌러 끄는 방식으로 바뀌면서 쉽게 걸리게 됐습니다. 게시물을 다른 섹션으로 옮기면 원래 섹션은 줄고 대상 섹션은 커지는데, `closestCenter` 충돌 감지는 "가장 가까운 컨테이너"를 기준으로 판단해 커서가 안 움직여도 판정이 원래 섹션으로 도로 뒤집히고, 그 되돌림이 다시 같은 뒤집힘을 유발해 `setLocalSections`가 끝없이 재호출됐습니다("Maximum update depth exceeded"). `pad-sections-board.tsx`의 충돌 감지를 `pointerWithin`(커서가 실제로 그 영역 안에 있을 때만 인정) 우선 + `closestCenter` 보조로 바꿔 해결했습니다.
- **담벼락·격자 순서 변경**: 두 레이아웃은 SECTIONS처럼 컬럼이 옆으로 나뉘어 있지 않고 섹션별로 이어붙인 하나의 평면 목록이라, 새 `pad-flat-board.tsx`(`FlatDragBoardView`)가 SECTIONS의 다중 컨테이너 `onDragOver` 로직 없이 `arrayMove` 한 번과 `rectSortingStrategy`만으로 재정렬합니다. 드롭한 위치의 이웃 게시물이 속한 섹션으로 자동 재배정되고, 대상 섹션 안에서의 앞뒤 이웃을 찾아 `/api/posts/[postId]/reorder`의 `previousItemId`/`nextItemId`를 계산합니다. 로컬 낙관적 갱신은 `sortLayoutPosts`로 먼저 정렬한 배열을 옮긴 뒤 대상 섹션 게시물에 순번을 다시 매겨야 합니다 — `WallLayout`/`GridLayout`이 렌더링 시점에 `position` 기준으로 다시 정렬하므로, 배열 순서만 바꾸고 `position` 값을 그대로 두면 화면이 바로 원래대로 튕겨 보입니다. Stream·Table·Timeline은 아직 이 작업 대상이 아닙니다(Stream은 항상 최신순으로 강제 정렬해서 별도 설계 판단이 필요하고, Table은 `dragDisabled` 계산까지는 이미 있었지만 감싸는 `DndContext`가 없어 동작하지 않는 죽은 코드였음).

변경한 경로: `components/pad/post-card.tsx`, `components/pad/section-column.tsx`, `components/pad/pad-sections-board.tsx`, `components/pad/pad-flat-board.tsx`(신규), `components/pad/pad-canvas.tsx`, `app/globals.css`

## 긴 패드의 초기 로드와 선택 기능 청크

- 보드 첫 응답은 섹션당 카드 30개까지만 받습니다. `SectionData.totalPostCount`는 전체 개수, `nextCursor`는 다음 페이지 유무를 나타내며 SECTIONS는 각 열 아래, 나머지 레이아웃은 보드 아래의 “더 보기”로 이어 받습니다. 요청은 섹션별로 중복을 막고 언마운트에서 취소합니다.
- 아직 받지 않은 카드가 있으면 수동 게시물 드래그를 막습니다. 화면 끝의 카드 다음에 실제로 어떤 카드가 있는지 모르는 상태에서 `nextItemId=null`을 저장하면 의도와 달리 섹션 맨 끝으로 이동할 수 있기 때문입니다. 섹션 자체의 이동은 계속 가능합니다.
- `lazy-post-composer.tsx`가 첨부 업로드·미디어 캡처·초안 복구를 포함한 `PostComposer`를 작성/수정할 때만 동적 import합니다. 작성 버튼에 포인터 또는 키보드 포커스가 닿으면 먼저 청크를 받아 실제 클릭 지연을 줄입니다.
- 카드에는 `content-visibility:auto`와 고유 높이 추정값이 있어 화면 밖 카드의 레이아웃·페인트를 건너뜁니다. `PostCard`와 `SectionColumn`은 `memo`로 감싸 설정 패널·상단 UI 상태만 바뀐 렌더가 카드 트리까지 전파되지 않게 했습니다. 페이지 상한은 네트워크/RSC/React 객체 수를, CSS·memo 경계는 이미 받은 카드의 브라우저 렌더 비용을 각각 제한합니다.
- `post-card.tsx`는 표시·반응·댓글만 담당하며 `@dnd-kit`을 import하지 않습니다. `sortable-post-card.tsx`가 `useSortable`과 transform/키보드 손잡이를 맡습니다. 보드에서 정렬 자체가 불가능하면 모든 글이 순수 `PostCard`를 쓰고, 하나라도 옮길 수 있으면 이동 불가 글도 드롭 기준 위치 측정을 위해 비활성 sortable로 등록합니다. 그래야 내 글을 다른 사람 글의 정확한 앞뒤에 놓을 수 있습니다. WALL/GRID의 평면 DnD 모듈 자체는 수동 정렬이고 모든 페이지를 받았으며 현재 사용자에게 이동 가능한 카드가 있을 때만 불러옵니다.
- `use-pad-events.ts`는 탭이 숨겨지면 EventSource와 재시도 타이머를 닫습니다. 탭이 다시 보이면 연결 후 전용 JSON 스냅샷을 받아 백그라운드 동안 놓친 재정렬까지 수렴합니다. 평상시 이벤트에서는 `router.refresh()`를 호출하지 않으며, 스냅샷 조회 도중 새 이벤트가 오면 낡은 응답을 버립니다. 여러 패드 탭이 사용자·서버 SSE 연결 상한을 계속 점유하지 않게 하기 위한 수명 주기입니다.
