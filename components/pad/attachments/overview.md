# 첨부 컴포넌트 개요

이 폴더는 게시물 첨부의 클라이언트 업로드 상태와 유형별 표시를 담당합니다.

- `use-attachment-upload-queue.ts`는 파일별 `대기·업로드 중·완료·실패·취소` 상태를 관리합니다.
- 실제 전송은 `XMLHttpRequest`를 사용해 파일별 진행률과 취소를 지원합니다.
- 한 번에 최대 3개만 전송하며 실패한 파일만 다시 시도할 수 있습니다.
- 대기 파일은 게시 버튼을 막지 않고 본문이 저장된 뒤 전송합니다. 취소한 파일은 다음 전체 저장에서 자동으로 되살리지 않으며 해당 항목의 재시도를 눌렀을 때만 다시 큐에 들어갑니다.
- 게시물 본문 저장과 첨부 전송은 별도 단계로 취급합니다. 일부 파일이 실패해도 성공한 게시물과 첨부는 유지합니다.
- `post-content-blocks.ts`의 전용 Markdown 상대 경로 링크를 사용해 첨부를 본문 문단 사이에 배치합니다. 파일 선택·촬영·드래그앤드롭·파일만 있는 이미지 붙여넣기는 현재 커서에 임시 블록을 자동 삽입하고, 업로드 성공 뒤 실제 첨부 ID로 교체합니다. 표시할 때는 문자열의 ID를 그대로 파일 주소로 쓰지 않고 현재 게시물 DTO에 실제로 포함된 첨부만 `AttachmentViewer`로 교체합니다. 전용 블록이 없는 과거 첨부는 상세 본문의 위쪽에 표시해 기존 데이터를 그대로 호환합니다.
- `file-rules.ts`의 `attachmentFilesFromClipboard`는 텍스트·HTML이 하나라도 있는 붙여넣기에서는 파일 항목을 버립니다. 일부 앱이 복사한 글과 렌더링 WebP를 함께 제공해도 글만 입력되며, 파일만 있는 클립보드에 한해서 기존 첨부 검증을 진행합니다.
- `attachment-viewer.tsx`는 이미지·PDF·영상·음성·링크·일반 파일을 같은 데이터 계약으로 표시합니다.
  링크는 16:9 썸네일과 제목·설명·호스트 출처가 있는 카드로 통일합니다. YouTube는 저장 URL에서
  영상 ID를 다시 계산해 고정된 `i.ytimg.com` 썸네일과 재생 표시를 쓰고, 일반 웹은 첨부 시점에
  검증해 저장한 `previewImageUrl`을 씁니다. 대표 이미지가 없는 과거 링크도 제목과 호스트 행으로
  표시됩니다.
- `upload-queue-list.tsx`는 파일 종류·크기와 각 파일의 진행률, 실패·취소·재시도 동작을 목록으로 표시합니다. 이미지에는 로컬 썸네일, 음성·영상에는 업로드 전 확인 가능한 재생기를 표시하며 object URL은 행이 사라질 때 폐기합니다. 업로드 전 X는 브라우저 큐만 정리하고, 업로드가 끝난 항목의 휴지통은 작성기의 영구 삭제 확인과 서버 삭제 API에 연결됩니다. 원형 선택 버튼은 업로드 중인 항목만 제외하고 일괄 작업 대상을 고릅니다.
- `media-capture.tsx`는 사용자 동작 후에만 카메라·마이크 권한을 요청하며 사진 촬영과 음성·영상 녹화 결과를 일반 `File`로 업로드 큐에 전달합니다. 호출자는 `modes`로 사진·음성·영상 중 필요한 기능만 노출할 수 있습니다.
- 미디어 캡처를 닫거나 컴포넌트가 해제되면 모든 카메라·마이크 트랙을 즉시 종료합니다.
- `office-viewer.tsx`는 서버의 Office→PDF 변환 준비 상태를 확인하며, 첨부를 닫거나 다른 문서로 이동하면 진행 중인 변환 확인 GET과 재시도 타이머를 함께 취소합니다.
- 영상과 음성은 자동 재생하지 않고 `preload="metadata"`로 원본 스트리밍만 사용합니다.
- 이미지 대체텍스트와 모든 첨부 캡션을 표시할 수 있습니다.
- `attachment-metadata-editor.tsx`는 이미지 대체텍스트와 모든 첨부의 캡션을 편집하며, `AttachmentViewer.onUpdateMetadata` 콜백으로 저장을 위임합니다. 대체텍스트는 300자, 캡션은 500자로 제한합니다.
- 편집 권한이 있을 때 첨부 순서 변경과 삭제 콜백을 노출합니다. 실제 권한은 API가 다시 검증해야 합니다.
- `sortable-attachment-list.tsx`는 단독 게시물 페이지에서 본문에 배치되지 않은 첨부만 dnd-kit 세로 목록으로 감쌉니다. 포인터·터치·키보드 손잡이를 제공하고, 드롭하면 본문 배치 첨부의 슬롯은 고정한 채 미배치 슬롯만 새 순서로 채워 기존 전체 첨부 정렬 API에 저장합니다.

지원 형식과 용량은 클라이언트에서 먼저 안내하지만, 최종 파일 시그니처·크기·권한 검사는 서버 첨부 API의 책임입니다.

## 음성 녹음이 VIDEO로 잘못 분류되던 버그 (수정됨)

`media-capture.tsx`의 음성 녹음(`mode: "audio"`)은 결과 File의 `type`을 `recorder.mimeType`으로 채우는데, Chrome 등 대부분 브라우저는 `MediaRecorder.mimeType`을 `"audio/webm;codecs=opus"`처럼 코덱 파라미터가 붙은 문자열로 돌려줍니다. 서버 검증(`lib/files/validation.ts`)은 WebM 컨테이너가 음성·영상을 구분하지 못하는 문제를 브라우저가 보낸 MIME으로 보정하는데, 그 비교가 정확히 `"audio/webm"` 문자열과만 일치했습니다 — 그래서 실제 녹음 파일(코덱 파라미터 포함)은 이 보정에 걸리지 못하고 항상 `mimeType: "video/webm"`, `attachmentType: "VIDEO"`로 저장됐습니다(업로드 자체는 성공하지만 첨부 유형이 잘못 붙는 조용한 버그). 코덱 파라미터가 붙은 문자열도 인식하도록 비교 조건을 넓혀 수정했습니다. 자세한 내용은 `lib/files/overview.md`.
## 이미지 최적화 이후 갱신

Pad 게시물의 빠른 업로드는 원본 수신·검증·저장만 기다립니다. 변환 완료는 별도
attachment.updated 이벤트의 imageRevision으로 표시 URL을 바꾸며 기존 본문 링크는 유지합니다.
업로드 진행률 99% 이후에는 ‘저장 확인 중’을 표시하고 변환을 게시 대기 상태로 표현하지 않습니다.
