# 게시물 작성 보조 개요

이 폴더는 게시물 작성기의 브라우저 상호작용을 기존 `post-composer.tsx`와 분리해 제공합니다.

카드의 `… → 게시물 수정`도 같은 작성기를 모달로 엽니다. 저장 시 `MarkdownEditorHandle.getMarkdown()`으로
현재 문서를 직접 읽어 필수값·길이를 검증하고 최초/첨부 확정 요청에 동일한 본문을 씁니다. Milkdown
변경 알림의 200ms 지연 중 저장해도 마지막 입력이 빠지지 않으며, 초기화 실패 시 textarea 값을 읽습니다.

보드에서 새 글을 작성할 때는 데스크톱의 투명 배경 우측 패널, 모바일의 실제 `visualViewport` 높이를 따르는 전체화면으로 표시합니다. 단독 게시물 페이지에서 수정할 때는 우측 패널을 만들지 않고 기존 게시물 영역 전체를 `presentation="inline"` 작성기로 교체하며 옆의 댓글은 유지합니다. 인라인 제목은 게시물 제목처럼 평평한 입력면을 쓰고 첨부 도구 막대와 저장·취소 동작은 같은 `PostComposer` 로직을 공유합니다. 모바일 새 글 작성기의 첨부 도구 막대는 키보드가 올라와도 바로 위에 남습니다.

- `markdown-editor.tsx`는 Milkdown CommonMark 입력 규칙으로 백틱 인라인 코드·제목·인용·목록·코드 블록을 입력 즉시 시각화합니다. 편집 결과는 HTML이 아니라 Markdown 문자열로 부모 상태에 전달하므로 기존 게시물·초안·API·DB 계약은 바뀌지 않습니다.
- Milkdown이 허용하는 `문자**@로 시작하는 강조**`는 표준 CommonMark가 게시 화면에서 literal 별표로 남기는 경계 사례입니다. `remark-relaxed-strong.ts`가 ReactMarkdown의 text 노드로 남은 이 표기만 strong 노드로 보정해 편집기와 게시 화면을 일치시키며, 정상 강조와 코드 노드는 건드리지 않습니다.
- 편집기와 읽기 화면의 코드 블록은 긴 줄의 가로 스크롤만 블록 안에 유지하고 세로 휠·터치 스크롤은 부모 편집기나 페이지로 이어집니다. 세로 overflow가 없는 코드 블록 위에서 아래 글로 이동하지 못하는 스크롤 고정을 피하기 위해 `overscroll-behavior`를 축별로 분리합니다.
- 파일 선택·촬영·이미지 붙여넣기는 현재 커서에, 본문 편집기로 드롭한 로컬 파일은 실제 드롭 좌표에 사람이 읽을 수 있는 전용 Markdown 링크를 자동 삽입합니다. 브라우저 MIME이 비어 있는 Office·HWP·일부 이미지도 확장자로 화면 유형을 분류하지만 서버는 파일 시그니처를 다시 검사합니다. Milkdown이 허용하지 않는 사용자 정의 프로토콜 대신 안전한 상대 경로 표식을 사용합니다. 업로드 전에는 브라우저 안의 임시 ID를 쓰고 저장이 끝나면 현재 게시물의 첨부 ID로 교체하므로 이미지·파일 여러 개를 문단 사이에 섞을 수 있습니다. 기존 첨부와 링크 목록의 본문 배치 버튼도 같은 경로를 사용합니다. 실패한 임시 블록은 공개 본문에서 제거하고 초안에는 남겨 재시도 위치를 보존합니다.
- 저장된 첨부와 새 업로드는 파일 종류·크기·상태가 보이는 목록으로 나눠 표시합니다. 상단에는 현재 첨부 수와 남은 개수를 항상 표시하고, 기존 첨부와 대기 링크까지 계정 20개·손님 5개 한도에 포함해 파일을 고르는 순간 초과 항목을 안내합니다. 로컬 이미지 썸네일과 음성·영상 재생기는 `objectURL`을 항목 수명 동안만 만들고 해제합니다.
- 목록의 원형 선택 버튼으로 저장 파일과 업로드 큐를 함께 여러 개 고를 수 있습니다. 한 번의 확인으로 서버 파일은 영구 삭제하고 로컬 항목은 큐와 본문 표식에서 제거하며, 서버 삭제에 실패한 항목만 선택 상태로 남겨 재시도할 수 있습니다. 실패·취소 큐는 헤더의 정리 버튼으로 즉시 비웁니다.
- `composer-attachment-metadata.tsx`는 바깥 게시물 `<form>` 안에 또 다른 form을 만들지 않는 인라인 대체텍스트·캡션 편집기입니다. 기존 첨부는 저장 버튼으로 즉시 PATCH하고, 새 파일은 임시 메타데이터를 보관했다가 업로드 성공 직후 해당 첨부 ID에 PATCH한 다음 게시를 확정합니다.
- 게시물 본문 저장 뒤 첨부나 링크 단계가 실패하면 `savedTarget` 상태와 안내 배너를 유지합니다. 이 상태에서 Esc·배경·닫기 버튼을 사용하면 성공한 내용은 서버에 남고 대기·실패 파일은 다시 선택해야 한다는 확인창을 거쳐, 조용히 부분 저장 상태를 잃지 않게 합니다.
- 일반 입력마다 문서를 다시 만들지 않고 외부 `value`가 현재 편집기 Markdown과 실제로 다를 때만 `replaceAll`합니다. 초안 복구는 반영하면서 커서와 실행 취소 기록은 보존하며, 편집기 초기화가 실패하면 같은 20,000자 제한의 일반 textarea로 전환합니다.
- `use-post-draft.ts`는 제목과 본문을 700ms 간격으로 브라우저 `localStorage`에 자동 저장합니다.
- 서버 렌더와 첫 클라이언트 렌더는 항상 전달받은 초기값을 사용하고, 저장된 초안은 마운트 후에만 확인해 hydration 결과를 바꾸지 않습니다.
- 저장된 초안을 자동으로 덮어쓰지 않고 사용자에게 복구 또는 삭제 선택을 제공합니다.
- 작성 내용이 남아 있으면 `beforeunload`로 탭 닫기와 새로고침을 경고합니다.
- 게시물 저장이 성공하면 `markSaved`로 로컬 초안을 지워야 합니다.
- 첨부 `File` 객체는 브라우저 재시작 후 복구할 수 없으므로 이 초안에는 저장하지 않습니다. 첨부 상태는 `components/pad/attachments/overview.md`를 따릅니다.
- 붙여넣기에 `text/plain` 또는 `text/html`이 있으면 본문 입력을 우선하고 클립보드가 함께 제공한 WebP 같은 보조 파일은 첨부하지 않습니다. 파일만 들어 있는 스크린샷·이미지 붙여넣기만 첨부 큐로 보냅니다.
- `link-preview-input.tsx`는 한 줄에 하나씩 최대 남은 첨부 수만큼 URL을 받아 `/api/link-preview`에서 동시에 3개씩 안전한 미리보기 DTO를 만듭니다. 성공한 링크는 게시물의 추가 대기 목록으로 옮기고 입력창을 비우며, 형식 오류·미리보기 실패·20개 첨부 한도를 넘은 링크만 입력창에 남겨 고칠 수 있습니다. 중복 URL은 자동 제외합니다.
- 링크 입력은 항상 `post-composer.tsx`의 `<form className="composer-form">` 안에서 렌더링되므로 자체 `<form>`을 두지 않습니다. 줄바꿈은 여러 URL 구분에 사용하고 `Ctrl/⌘ + Enter` 또는 `type="button"` 버튼으로만 추가해 바깥 게시물 폼이 뜻하지 않게 제출되지 않도록 합니다.

로컬 초안에는 사용자가 입력한 본문이 남을 수 있으므로 공용 기기에서는 저장 완료·취소 시 삭제할 수 있게 해야 합니다. 서버 동기화 초안은 보드 권한·보존 기간·개인정보 정책을 별도로 확정한 뒤 추가합니다.
