# components/forms 개요

설문(구글 설문지 + 서명) 편집 화면과 응답 화면(`/s/[slug]`)입니다.

설문 목록은 `/forms`, `/forms/open`, `/forms/drafts`, `/forms/closed` 정식 경로로 나뉩니다. `FormList`가 검색·정렬 상태와 함께 공용 보관함 헤더·카드 그리드를 그리고, `app/(workspace)/forms/(library)/layout.tsx`는 교사 권한 경계만 담당합니다. 응답 중·초안·마감은 본문 상태 칩으로만 전환하며 사이드바에는 `내 설문`과 실제 최근 방문 6개만 표시합니다. 최근 목록은 `FormVisit.lastVisitedAt` 순이라 설문 수정만으로 순서가 바뀌지 않습니다. 예전 주소는 프록시가 새 경로로 옮깁니다.

한 파일에 몰지 않고 나눈 이유 — 퀴즈 편집기(`components/quiz/quiz-editor.tsx`)가 1439줄까지 자라서 유형 하나를 고치려 해도 파일 전체를 훑어야 했습니다. 설문은 유형이 13가지라 같은 방식으로는 더 나빠집니다.

## `clientId`가 따로 있는 이유

`FieldDraft`는 DB의 `FormField`에 `clientId`를 더한 것입니다. `id`는 서버가 준 것이라 아직 저장 안 된 질문에는 없는데, React의 key로 쓰려면 처음부터 있는 안정된 값이 필요합니다. 배열 index를 key로 쓰면 순서를 바꿀 때 입력 중이던 값이 엉뚱한 칸으로 따라갑니다. 보기에도 같은 `clientId`를 붙여 저장 중 추가·삭제와 답변별 분기 규칙이 DB ID 발급 전부터 같은 항목을 가리키게 합니다.

## 유형을 바꿀 때는 초기화가 아니라 병합입니다

`changeFieldType()`(field-model.ts)이 정본입니다. 질문 문구·설명·필수 여부는 유형과 무관하므로 남기고, 유형 고유 설정만 기본값으로 되돌립니다. 초기화해 버리면 유형을 잘못 고른 사람이 질문을 다시 타이핑해야 합니다.

보기는 "보기를 가지는 유형끼리" 옮길 때만 유지합니다(객관식 ↔ 체크박스 ↔ 드롭다운 ↔ 그리드). 그리드의 보기는 곧 열이라 그대로 쓸 수 있습니다.

새 유형에 붙을 수 없는 응답 확인은 버립니다 — 남겨 두면 저장 스키마(`discriminatedUnion`)가 거부합니다.

질문 유형 선택은 브라우저 기본 `<select>` 대신 공용 `ContentCardMenu`·`ContentCardMenuItem`·
`ContentCardMenuSection`을 사용합니다. 기존 분류와 아이콘에 짧은 설명·현재 선택 표시를 더하고,
body 포털·모바일 메뉴·바깥 클릭 닫기는 목록 카드와 같은 구현을 재사용합니다. 메뉴 높이는
최대 480px로 제한하고 다시 열 때 현재 선택 항목이 보이게 하며, 방향키로 유형을 이동할 수 있습니다.

## 서명 입력은 캔버스, 저장은 정규화 좌표입니다

입력은 `signature_pad`가 캔버스에 가변 굵기 베지어 곡선으로 그립니다. `toDataURL()` 이미지는 저장하지 않고 획이 끝날 때 CSS 픽셀 좌표를 0~1로 정규화하며, 압력과 획 내부 상대 시간도 함께 보존합니다. 기존 `{x,y}` 좌표도 계속 읽습니다. 응답 상세·인쇄처럼 읽기 전용인 곳은 같은 좌표를 SVG로 그리므로 서명 파일이나 별도 다운로드 권한이 필요하지 않습니다.

## 응답을 받는 중에도 편집할 수 있습니다

`status === "OPEN"`이어도 질문 추가·수정·유형 변경·삭제가 가능합니다. 저장해도 설문은 계속 응답을 받습니다.

자동/수동 저장 중에도 편집기 전체를 `inert`로 막지 않습니다. 저장 응답이 돌아오기 전에 질문이나
보기를 더 고쳤다면 `reconcile-form-save.ts`가 서버의 새 `updatedAt`과 영속 ID만 현재 로컬 문서에
합치고, 사용자가 뒤이어 입력한 내용과 순서는 보존합니다. 새 질문·보기의 `clientId`를 실제 DB id로
그대로 사용하므로 다음 저장에서 같은 항목을 다시 생성하거나 낡은 문서 버전으로 충돌하지 않습니다.

응답이 달린 질문을 지우려 하면 저장 API가 409와 응답 건수를 돌려주고, 편집기가 "응답 N건이 함께 지워집니다"를 보여 준 뒤 그 재시도 한 건에만 `confirmDestructive`를 붙입니다. 확인창이 열린 동안 설문이 또 바뀌면 승인을 재사용하지 않고 현재 문서로 다시 저장하게 하며, 네트워크 실패 뒤 다음 저장에 승인 플래그가 남지 않습니다.

OPEN 설문은 개요와 편집기 양쪽의 `응답 마감` 버튼으로 `POST /close`를 호출합니다. 마감 뒤에도
링크와 기존 응답은 유지되고 `다시 응답 받기`로 재개할 수 있습니다.

상단 상태는 모바일 공간을 차지하는 문구 대신 색상 토큰을 쓴 점으로 표시합니다. 초록은 응답 가능,
빨강은 초안 또는 마감으로 응답 중지 상태이며, 접근성 이름과 툴팁에는 상태 문구를 남깁니다.
설정의 `closedMessage`는 직접 마감·기간 종료·정원 도달 뒤 공개 응답 링크와 제출 직전 마감 오류에
같이 사용하고, 초안과 응답 시작 전에는 각각의 기본 안내를 유지합니다.

설문 개요의 질문·응답·상태 요약은 모바일에서도 3열 한 행을 유지하도록 공용 `StatCard`의
`compactMobile` 변형을 씁니다. 상태 값은 문구를 반복하지 않고 초록(응답 가능)·빨강(응답 중지)
아이콘으로만 보이며 접근성 이름에는 상태가 남습니다. 최하단 작업과 응답 링크의 복사·열기 작업은
모바일에서 동일 폭 아이콘 버튼, `sm` 이상에서 아이콘+문구로 확장됩니다.

`useDocumentSave`의 30초 주기 자동 저장을 명시적으로 사용합니다. 변경이 없거나 이미 저장 중이면
요청하지 않으며, 자동 저장 중 다시 편집한 내용은 dirty 상태로 남겨 다음 주기에 저장합니다.

저장 요청 뒤 추가 편집이 있었다면 이전 문서에 대한 `400 + FORM_VALIDATION_ERROR`를 표시하지 않습니다.
현재 문서의 검증 오류는 별도 상태로 안내하고 새 편집 시 지우지만, 실패를 저장 성공으로
처리하지 않으므로 다음 자동저장이 현재 문서를 재시도합니다. 태그 없는 400(ID 불일치 등)·401/403·409 버전 충돌·서버/네트워크
장애는 입력 오류와 분리해 새 편집만으로 숨기지 않습니다. 파일 유형 최소 1개 제한도 유지합니다.

## 날짜는 저장 직전에만 변환합니다

`FormSettingsPanel`이 다루는 `openAt`/`closeAt`은 `<input type="datetime-local">`이 읽는 로컬 시각 문자열("2026-09-01T09:00")입니다. 이 형태는 서버의 `z.iso.datetime()`을 통과하지 못합니다(초·타임존이 없습니다). `form-editor.tsx`가 저장 직전에만 `toIsoOrNull()`로 UTC ISO로 바꾸고, 편집 중에는 계속 로컬 문자열 그대로 들고 있습니다 — 매 입력마다 변환하면 입력 중인 값과 표시되는 값이 반올림 오차로 미묘하게 어긋날 수 있습니다.

응답의 DATE 필드는 별도 규칙입니다. 연도와 시간이 있으면 브라우저 로컬 시각을 ISO로 바꿔 보내고, 연도가 없으면 `MM-DD` 또는 `MM-DDTHH:mm`을 그대로 보냅니다. 서버와 화면이 같은 `validateAnswer()`로 실제 달력 날짜를 검사합니다.

## 저장할 때 낡은 문서인지 함께 알려줍니다

`form.updatedAt`을 로드 시점 그대로 들고 있다가 저장할 때 `expectedUpdatedAt`으로 돌려보냅니다. 다른 탭이나 공유받은 EDITOR가 먼저 저장했으면 서버가 409 `needsReload`를 돌려주고, 편집기는 자동으로 합치지 않고 에러 문구로 새로고침을 안내합니다 — 자세한 이유는 `lib/forms/overview.md`의 "낙관적 동시성" 참고.

## 문항 섞기는 서버 seed로 초기 상태에서 한 번만 합니다

`shuffleFields`가 켜져 있으면 한 번 섞은 순서를 응답 내내 유지해야 문항이 널뛰지 않습니다. 렌더
함수 안에서 `Math.random()`을 부르면 이 프로젝트의 `react-hooks/purity` 규칙에 걸리고(같은
입력엔 항상 같은 출력이어야 함), 서버와 브라우저가 서로 다른 순서를 만들면 hydration도
어긋납니다. 공개 설문 서버 페이지가 익명 쿠키 또는 사용자·응답 식별자로 안정적인
`shuffleSeed`를 만들고, `FormRunner`는 그 seed를 사용해 `useState` 초기화에서 한 번만 섞습니다.
그 뒤로는 이미 정해진 순서를 읽기만 합니다.

보기의 `shuffleOptions`도 같은 초기화에서 필드별로 한 번만 적용합니다. 둘 다 원본을 바꾸지
않는 Fisher-Yates 함수(`lib/forms/shuffle.ts`)를 공유합니다.

## 첫 화면 데이터는 서버가 읽습니다

목록의 `accessLevel`은 API와 같은 `lib/forms/access-level.ts` 판정 함수를 사용합니다. 잠긴 설문은
일반 소유자·편집자도 보기 전용으로 표시하고, 삭제·공동 작업자 관리는 소유 권한에만 노출합니다.
보기 전용 사용자의 응답 링크 공유창에는 단축 링크 관리 기능을 노출하지 않습니다.

설문 목록, 편집기, 공개 응답과 기존 응답 수정 페이지는 마운트 뒤 정의를 다시 fetch하지 않습니다.
Server Component가 세션과 익명 응답 쿠키를 확인하고 `lib/forms/public-form-data.ts` 등의 공용
로더로 DTO를 만든 뒤 초기 prop으로 전달합니다. 같은 GET Route Handler도 이 로더를 재사용합니다.
브라우저 요청은 저장·발행·제출·파일 업로드와 사용자가 개별 응답 탭을 연 뒤의 상세 조회에만 씁니다.
목록의 반복 설문 링크는 자동 prefetch를 끄므로 현재 페이지에 보이는 모든 편집기 RSC를 동시에
미리 받지 않습니다. 번호형 페이지 탐색도 패드·퀴즈와 같은 `PageNumberNavigation`을 사용하며 현재
검색·정렬 조건을 URL에 보존합니다.

## 설정 패널은 `components/ui/modal.tsx`를 씁니다

`FormSettingsPanel`이 처음에는 배경 오버레이·포커스 트랩·Escape 처리를 직접 만들었습니다. `Modal variant="side"`(패드 보드 설정 패널이 이미 쓰는 것과 같은 조합)로 바꿔, 포커스 복원 같은 미묘한 동작이 화면마다 따로 옳고 그른 상태가 되지 않게 했습니다.

## 서명 다운로드

서명은 계속 정규화 좌표 JSON으로만 저장합니다. 개별 응답에서는 무손실 SVG로 내려받고, 응답
상단의 `첨부·서명 ZIP`은 파일 업로드 질문의 원본과 SVG 서명을 응답자·질문별 폴더에 함께 넣습니다.
`lib/forms/response-files-export.ts`가 첨부 원본은 파일 스트림으로 이어 붙이고 SVG는 ZIP의 deflate
압축을 그대로 받게 하므로 전체를 메모리에 올리거나 PNG/JPG로 불필요하게 래스터화하지 않습니다.
XLSX의 `응답자` 열과 ZIP 최상위 폴더는 `lib/forms/export-names.ts`가 만든
`표시 이름_응답ID끝6자리`를 똑같이 사용합니다. 한글은 NFC로 정규화하므로 Python 등에서 두 값을
그대로 비교할 수 있고, 같은 사용자가 복수 응답해도 폴더가 합쳐지지 않습니다.
두 Route Handler 모두 설문 열람 권한과 요청 빈도를 다시 검사하고 응답에는 `private, no-store`를
적용합니다.

## 서명 입력기 청크

`field-card.tsx`와 `answer-fields.tsx`는 `signature-pad.tsx`를 정적으로 가져오지 않습니다. `signature_pad` 패키지와 캔버스/ResizeObserver 코드는 실제 서명 질문이 편집기 또는 응답 화면에 나타날 때만 동적 청크로 로드합니다. 일반 텍스트·선택형 설문은 서명 엔진을 내려받거나 초기화하지 않습니다. 저장 형식과 내보내기 규칙은 위의 정규화 좌표 JSON 계약을 그대로 유지합니다.

## 긴 설문 편집기 성능

`form-editor.tsx`의 설정 패널과 QR 공유 다이얼로그는 버튼을 열 때만 동적 청크로 마운트하며 포인터·키보드 포커스에서 미리 받습니다. 질문 카드의 뒤쪽 섹션 분기 후보는 섹션 구조·제목·순서가 바뀔 때만 다시 계산합니다. 일반 질문 한 글자 입력마다 카드별로 전체 질문을 `flatMap`하던 O(질문²) 계산은 하지 않습니다. `.form-editor-field`에는 `content-visibility:auto`를 적용해 긴 설문에서도 화면 밖 질문의 하위 레이아웃과 페인트를 건너뜁니다.

설문과 퀴즈 편집기가 공유하는 `lib/editor/use-list-drag.ts`는 실제 항목을 끄는 동안에만 non-passive `touchmove`를 등록합니다. 평상시 화면 스크롤에는 이 리스너가 없어 브라우저의 compositor 스크롤 경로를 막지 않습니다.

## 섹션 분기와 파일 질문

`SECTION_HEADER`는 공개 응답 화면에서 실제 페이지 경계입니다. 객관식·드롭다운 보기마다 뒤쪽
섹션 또는 바로 제출을 지정하며, `FormRunner`와 제출 API가 모두 `reachableFormFields()`를 써서
같은 경로만 검사합니다. 새 보기의 `clientId`는 저장될 실제 보기 ID이므로 첫 저장 전에도 이동
경로를 지정할 수 있습니다. 분기는 섹션당 하나만 허용하므로 분기 질문을 원본 바로 뒤에 복제할
때는 보기·문구만 복사하고 복제본의 분기 규칙은 비워 유효하지 않은 문서를 만들지 않습니다.
파일 질문은 로그인 사용자만 사용할 수 있고 선택 즉시 임시 업로드한
파일 ID를 최종 제출에서 답변에 귀속합니다.
