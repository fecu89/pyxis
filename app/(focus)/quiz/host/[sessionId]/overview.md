# app/host/[sessionId] 개요

LIVE 세션 진행 콘솔(클라이언트 컴포넌트, `socket.io-client`). 마운트 시 `GET /api/quiz/sessions/[sessionId]`로 PIN·퀴즈 제목·참여자 목록을 가져오고, 소켓으로 `session:join` 후 `host:start`/`host:reveal`/`host:show-leaderboard`/`host:next-question`/`host:end`/`host:skip-sequence`를 버튼으로 emit한다. 문항이 열리기 전 서버가 절대시각 3개(`countdownStartsAt`·`readingStartsAt`·`startsAt`)를 담아 `question:sequence`를 보내고, 클라이언트는 그 시각과 시계를 비교해 단계를 그린다(`lib/quiz/question-sequence.ts`의 `sequenceStageAt`) — 2,000/3,000점(2배 이상) 문항만 배수 강조 화면이 끼어들고, 1,000점 문항은 곧장 3·2·1 카운트다운으로 간다. `host:skip-sequence`는 이 대기를 건너뛰어 보기를 즉시 연다. 문항 시간 만료는 서버가 자동으로 처리하며, 호스트의 `host:reveal`은 조기 공개 버튼이다. `question:reveal` 뒤에는 설명 시간을 위해 화면이 유지되고, 호스트가 `host:show-leaderboard`를 보낸 뒤에만 TOP 3를 렌더링한다. 서버가 내려주는 리더보드 payload는 현재 TOP 3와 이번 문항 이전 TOP 3의 합집합(최대 6명, `lib/quiz/live-leaderboard.ts`)이라 순위에서 밀려난 이전 3위도 함께 실려 온다 — 같은 participant 카드가 DOM을 유지한 채 이전 자리에서 새 자리로 이동하고(들어온 자리는 위로, 밀려난 자리는 3행 아래로 빠지며 사라진다), 점수가 카운트업된다. 재접속 시 강조 화면·현재 문항·정답·순위 단계도 복구한다. 이벤트 목록·페이로드는 `structure.md`의 "대표 상호작용 흐름" 절 참고.

`question.type`이 `SHORT_ANSWER`면 보기 목록 대신 "주관식" 안내만 표시하고(호스트는 입력하지 않음), `question:reveal` 결과도 `choiceBreakdown` 대신 허용 정답 목록 + 정답자 수로 다르게 렌더링한다(`QuestionReveal`이 `type`으로 분기되는 유니온 타입).
