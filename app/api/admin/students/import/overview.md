# 학생 Excel 명단 등록

`GET`은 `학교, 학년, 반, 번호, 이름` 열이 준비된 `.xlsx` 양식을 내려주고(파일명 `forms.xlsx` — 서비스 브랜딩 없이 범용으로 두어 다른 시스템 제출용으로도 재활용 가능), `POST`는 같은 파일을 서버에서 다시 읽어 미리보기 또는 실제 등록을 수행합니다. 클라이언트의 미리보기 결과를 신뢰하지 않고 등록 요청 때 파일 전체를 재검증합니다.

- 파일은 3MB, 학생은 500명으로 제한합니다. 첫 시트만 읽으며 수식 셀, 누락 열, 범위 밖 숫자, 파일 안에서 중복 생성되는 아이디를 거부합니다.
- 접두어는 1~10자 영문자·숫자만 허용합니다. 아이디는 `{접두어}{학년 1자리}{반 2자리}{번호 2자리}`, 초기 비밀번호는 **아이디와 동일**합니다(예전 `{이름 첫 글자}{학생 코드}` 방식은 한글이 섞여 로그인이 불가능한 사고가 있어 폐기).
- 기존 아이디가 하나라도 있으면 전체 등록을 중단합니다. 학교·학년·반과 학생 계정 생성은 하나의 직렬화 트랜잭션으로 처리해 일부 학생만 들어가는 상태를 남기지 않습니다.
- 전체관리자는 누락된 학교까지 만들 수 있습니다. 학교 대표교사는 자기 학교의 명단만 등록할 수 있고 새 학교는 만들 수 없습니다.
- 생성 계정은 `mustChangePassword = true`라 최초 로그인 뒤 비밀번호 변경 전에는 다른 화면과 API에 접근할 수 없습니다. 평문 초기 비밀번호는 DB나 감사 로그에 저장하지 않고 등록 응답에서 한 번만 관리자에게 전달합니다.
- 최대 명단의 scrypt 해시가 일반 요청보다 오래 걸릴 수 있어 이 관리자 전용 Route Handler의 실행 한도는 300초로 선언합니다. 해시는 4개씩 병렬 계산하되 보안 비용을 낮추지 않습니다.
