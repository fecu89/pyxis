# API 개요

Route Handler는 세션만 확인하지 않고 대상 보드의 DB 역할과 기능별 권한을 함께 검사합니다.

공개 읽기 API를 제외한 생성·수정·삭제·접근 요청 처리는 `requireCurrentUser()`로 로그인 사용자를 확인하며, 접근 요청 승인과 멤버 추가는 트랜잭션으로 처리합니다.

신규 로그인 사용자는 `/api/onboarding`에서 닉네임과 학교·역할에 맞는 반/부서를 원자적으로 저장하기 전까지 인증·프로필 이미지·온보딩 API만 사용할 수 있습니다.

## 공통 요청·응답 경계

- 모든 쓰기 Route Handler는 `assertSameOrigin(request)`를 거칩니다. 공개 참여·설문 제출도 쿠키를 사용하므로 예외가 아닙니다.
- 공개 JSON과 문서 전체 저장처럼 크기가 커질 수 있는 요청은 `readJsonWithLimit()`로 실제 스트림 바이트를 제한합니다. `Content-Length`가 없거나 거짓이어도 읽는 도중 다시 검사하며, 잘못된 JSON은 400, 상한 초과는 413입니다.
- `apiError()`는 인증 401, 권한 403, 요청량 429(`Retry-After`), 일시 과부하 503을 구분합니다. Prisma·런타임 내부 오류는 사용자 입력 400으로 숨기지 않고 내부 문구를 제거한 500으로 반환합니다.
- 오류 응답과 개인정보·관리 데이터 응답은 `Cache-Control: private, no-store`를 사용합니다. Zod 경로·DB 제약조건·파서 내부 문구는 클라이언트에 노출하지 않습니다.
- 목록 API는 고정 페이지 크기 또는 cursor 상한을 두며, 패드 글처럼 계속 늘어나는 목록은 cursor를 사용합니다. 대량 변경은 클라이언트 배열을 그대로 순차 실행하지 않고 중복 제거·`createMany`·작은 동시성 묶음을 사용합니다.

## 요청량 제한과 동시성

로그인 사용자는 가능하면 사용자 ID를 제한 키로 씁니다. 학교 NAT에서는 학생 수백 명이 같은 공인 IP를 공유하므로 정상 로그인·퀴즈 참여를 IP 한 버킷으로 세면 안 됩니다. 공개 퀴즈 참여는 교실 수용량용 넓은 IP 상한과 잘못된 PIN용 좁은 상한을 분리합니다.

중복 제출은 사전 조회만으로 막지 않습니다. 퀴즈 답안은 DB 고유 제약을 최종 방어선으로 두고, 동시 요청 중 패배한 요청도 이미 저장된 답안을 다시 읽어 동일한 성공 결과로 수렴합니다. 패드 위치 변경과 생성은 공통 부모 행 잠금 뒤 현재 이웃을 다시 계산합니다.

`yarn verify:api-boundaries`는 서버나 DB 없이 쓰기 API의 same-origin, 공개 JSON 본문 상한, 학교 NAT 제한 키, 회원가입 제한 순서, 대량 초대와 답안 중복 제출 경계를 정적으로 검사합니다.
