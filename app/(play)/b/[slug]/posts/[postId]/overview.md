# 게시물 상세 라우트

패드 카드 하나를 읽는 독립 페이지입니다.

- URL은 `/b/{slug}/posts/{postId}`입니다. 패드 카드의 클릭·Enter·Space 동작이 이 경로로 이동합니다.
- 한글 slug 경로는 `lib/board/route-paths.ts`에서 디코딩 후 한 번만 인코딩합니다. Next 라우터의
  `%EC...` params를 다시 인코딩해 `%25EC...`가 되던 버그를 막고, 이미 복사된 이중 인코딩 주소도
  최대 2회 디코딩해 정상 게시물로 연결합니다.
- `lib/board/queries.ts`의 `getBoardPageData(..., { focusPostId })`를 사용하므로 패드 본문과 같은 공개 범위, 비밀번호, 멤버십, 게시 상태 권한을 적용합니다.
- 링크 공개 패드는 익명으로 읽을 수 있지만 댓글·반응·수정처럼 로그인 또는 멤버 권한이 필요한 동작은 기존 capability 값으로 계속 제한합니다.
- 공개 가능한 게시물은 게시물 제목과 본문 요약을 메타데이터에 사용하고 패드 OG 이미지를 공유 썸네일로 재사용합니다. 보호된 패드와 비공개 게시물은 제목·본문을 노출하지 않고 기본 pyxis 메타데이터를 사용합니다.
- 게시물을 찾을 때 전체 패드의 게시물을 내려받지 않고, 해당 ID의 게시물만 섹션 안에서 조회합니다.
- 본문과 댓글을 데스크톱에서는 두 칸, 모바일에서는 한 줄로 배치합니다. 페이지 nav 중앙에는 현재 패드 이름을 표시하고 오른쪽에는 테마 같은 전역 동작만 둡니다. 섹션은 게시물 제목 상단에 한 번만 표시하며 댓글 수는 댓글 패널에서만 보여줍니다.
- 게시물 수정·삭제는 제목 영역 오른쪽 위의 작은 `게시물 관리` 더보기 메뉴에 모읍니다. 수정을 누르면 별도 모달이나 우측 패널을 만들지 않고 왼쪽 게시물 영역 자체가 전체 너비 인라인 `PostComposer`로 전환되고 댓글 영역은 그대로 남습니다. 저장하면 같은 자리에서 읽기 화면으로 돌아오며 삭제하면 원래 패드로 이동합니다.
- 본문은 카드와 같은 Markdown 제목 계층으로 렌더링합니다. 본문 전용 상대 경로 블록은 해당 문단 사이에서 실제 첨부로 바꾸고, 블록이 없는 과거 첨부는 본문 위에 표시합니다.

## 확인한 회귀 항목

- 카드 클릭과 키보드 Enter 이동
- 상세 URL 직접 진입과 패드로 돌아가기
- 권한 사용자의 게시물 영역 인라인 수정·저장·취소
- 제목 오른쪽 관리 메뉴와 nav의 중복 관리 버튼 부재
- 커서 위치 첨부 블록과 배치하지 않은 과거 첨부의 위쪽 표시
- 익명 공개 열람 시 댓글 작성·수정·삭제 UI 차단
- 390px 모바일에서 가로 넘침 없는 1단 레이아웃
- 데스크톱 2단 레이아웃과 댓글 sticky 동작
- 라이트·다크 모드 색상 대비
- 게시물 제목·본문 요약·패드 OG 이미지 메타데이터
- 한글 slug의 정상 인코딩 URL 생성과 기존 이중 인코딩 URL 직접 진입
